# ADR-009：V1 两级主体身份模型 —— 家庭账号（家长）+ 学生子账号（PD-016）

- **状态**：Accepted（2026-09-08；落地依赖 ACR-001 批准）
- **日期**：2026-09-08
- **决定者**：用户（M002 契约完整性审查逐项确认 b1d4 / E1~E4）+ Project Master
- **关联**：`docs/PROJECT_STATUS.md`（PD-016）、`docs/adr/ADR-005.md`（扩展而非取代）、`docs/changes/ACR-001.md`、`docs/changes/CR-001.md`、`docs/DATA_MODEL.md`（DATA-002）

## Context

M002 契约完整性审查（2026-09-08）揭示真实使用闭环：**作业登记与完成后拍照上传由学生自主完成，家长只做兜底**（纠错识别归属、驳回重拍、跨学生总览与报告）。ADR-005"纯家庭模式"仅支持家庭账号（家长）单角色、学生档案仅为评定对象，无法承载"学生用自己设备自助操作本人数据"的场景。

## Problem

V1 身份模型是否应引入"学生子账号"？若是，边界与授权粒度如何定义且不破坏 ADR-005 的家庭级隔离与 ADR-002 的范围约束？

## Options

| 方案 | 说明 |
| --- | --- |
| A. 维持家庭单角色（学生操作 = 家长设备上选择学生档案） | 实现最省，但与"学生独立设备自助登记/拍照"的真实使用不一致；且家长设备代操作的鉴权主体语义不清 |
| B. **两级主体：家庭账号（家长）+ 学生子账号**（完整登录账号，绑定 student_id） | 学生可独立登录操作本人数据，家长管理全家并兜底；家庭级数据隔离不变（**采用**） |
| C. 两级主体 + 更多角色（班级/教师/审批） | 超出 V1 边界（ADR-002），否决 |

## Decision

- **主体类型两种**：
  - `family`（家庭账号 / 家长角色）：管理本家庭全部学生档案与数据、开通/停用学生账号、执行兜底操作（归属/驳回/删除、跨学生总览与报告）
  - `student`（学生子账号）：绑定某个学生档案，仅能查看与操作**本人**数据（本人作业登记单、本人照片与归属结果）
- **账号形态**：学生子账号 = 完整登录账号（登录名 + 口令哈希，口令策略复用 M001 家庭账号 scrypt + 爆破退避）；由家长在创建/编辑学生档案处开通或停用（默认不开通）；会话机制复用（主体类型化：family/student）
- **授权规则**：数据隔离仍以 `family_id` 为主边界（ADR-005 不变）；在家庭内按主体细分——`student` 主体自动限定本人 `student_id`，不得传他人 `student_id`；跨主体/跨家庭一律 404（对外不泄露存在性，沿用既有语义）
- **功能面（V1）**：
  - 学生端：创建/编辑**本人**作业登记单、拍照上传、查看本人照片归属/完成度与待确认项、对自己照片执行 assign/confirm/reject/删除（本人数据自处理）
  - 家长端：跨学生总览与报告查看、手动关联/驳回/删除兜底、账号与学生档案管理
- **语义映射修正（相对 ADR-005）**：需求语境"学生上传"→ 学生（或其家庭家长代传）在本人档案上下文上传；"教师创建任务"→ 家长创建，且 V1 允许**学生创建本人档案下的作业登记单**（登记单归属细节见 CR-001）；"家长查看报告"→ 家长端 + 学生端可查看本人当日状态
- **生效路径**：本 ADR 即日 Accepted（决策事实）；代码与契约落地经 `ACR-001`（M001 认证/授权面变更）+ `CR-001`（任务/档案数据面相关）批准后实施；ADR-005 相应标注扩展

## Reason

- 两级主体是"学生真实自助 + 家庭级隔离 + 家长兜底"的最优交点；比多角色体系（C）轻，比纯家庭单角色（A）更贴合用户确认的真实闭环
- 家庭隔离仍是唯一外部边界，学生子账号是家庭**内部**的角色细分，不引入多租户/班级域（ADR-002 约束保持）

## Consequences

- DATA-002：学生档案增加子账号字段（登录名可空 UNIQUE + 口令哈希，或独立凭据表——ACR-001 定稿）；`auth_sessions` 主体类型化
- 共享 AuthContext / 鉴权中间件：从"family_id"升级为"subject（type + id）→ 可得 family_id/student_id 上下文"，各模块鉴权改为双层过滤（family 全局 / student 本人）
- M001 Frozen 认证/会话/学生档案 API 面受影响 → `ACR-001`
- M001~M007 全部后续契约的 Security 段落引用本 ADR 的主体模型
- 审计：会话登录/登出、兜底与删除操作需记录主体类型与 id
- 风险：子账号引入口令/越权新面 → 见 `RISK-007`
