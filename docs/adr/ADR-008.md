# ADR-008：学校基础字典 —— 全局共享只读公共基础数据（V1 增补）

- **状态**：Accepted
- **日期**：2026-09-08
- **决定者**：用户（M001 开发输入确认，四项）+ Project Master
- **关联**：`docs/requirements/REQ-009.md`、`docs/DATA_MODEL.md`（DATA-011）、`docs/modules/M001/`（契约修订）、`docs/adr/ADR-002.md`、`docs/adr/ADR-005.md`

## Context

用户 M001 开发输入提出：需要增加"学校基础资料"，且学生档案须记录学生所在学校。
原 V1 需求显式禁止"学校管理 / 班级管理 / 复杂教师平台 / 多租户"（ADR-002、ADR-005），此处禁止的是**学校域管理系统**，而非作为学生档案属性的"学校基础字典"。

## Problem

学校基础资料以什么形态落地？（数据归属 / 共享范围 / 维护方式）是否触碰 ADR-005 家庭数据隔离边界与 ADR-002 禁止范围？

## Options

| 方案 | 说明 |
| --- | --- |
| A. 家庭自有学校列表 | 每个家庭各自维护学校名单，不越 ADR-005 隔离边界；但多家庭同校时数据重复、名称不一致，未来按学校归档困难 |
| B. **全局共享字典 + seed 预置（采用）** | `schools` 表全局一份（不带 `family_id`），初始数据随数据库预置；学生档案 `school_id` 必填引用；V1 不提供写接口/维护 UI（后台维护预留，暂不开发） |
| C. 全局共享字典 + 后台维护模块 | 功能完整，但超出 V1 范围（"只允许预留，不允许提前实现"，ADR-002） |

## Decision

- 新增全局公共数据实体 **DATA-011 学校字典（`schools`）**：字段 `school_id` / `name` / `stage`；**全局共享只读**，不归属任何 `family_id`，不纳入 ADR-005 家庭数据隔离（公共基础数据例外）
- V1 数据写入仅经**数据库初始化 seed 预置**（预置常用中小学，覆盖 V1 起步的"小学"学段；后续补充走变更流程）
- 学生档案（DATA-002 / `students`）新增**必填 `school_id`**（FK→`schools`），删除原自由文本 `school` 字段；创建/更新学生档案必须选择已预置学校（无则 422）
- 字段范围 = **名称 + 学段**（`stage` 建议值 `primary/junior/senior`，文本存储不写死枚举，V1 起步 primary；档案页展示如"实验小学 · 小学"）
- **后台维护功能（新建/改名/停用学校）暂不开发**，仅预留边界，未来以变更流程评估（可能新增模块或移交公共基础数据域）
- 消费范围：**仅 M001 档案关联**；M007 今日报告展示学校名称留待 M007 契约时实现；M002~M006 无学校逻辑

## Reason

- 全局字典保证学校名称全局一致、可防重复建档错别字，未来可按学校归档/统计（学生档案已必填关联）
- seed 预置 + 无写接口是最小实现，符合 V1"真实可运行"与范围控制
- 档案必填学校 + 只读字典，录入成本低且报告数据完整

## Consequences（与 ADR-002 / ADR-005 的关系）

- **不改变 ADR-002/005**：学校管理域（学校账号、班级、多教师、学校级权限、多租户）**仍然禁止**；`ADR-005`"无学校"澄清为"无学校账号与学校域管理"
- `schools` 为公共只读基础数据，是 ADR-005 家庭隔离的**唯一例外类别**（同性质后续公共字典沿用此模式需另走变更评估）
- M001 契约修订：`MODULE_DATA.md` 增 `schools` 表、`students.school_id`；`MODULE_API.md` 增 API-M001-012（学校只读列表）并修订档案 API
- 数据模型：`DATA_MODEL.md` 登记 DATA-011
