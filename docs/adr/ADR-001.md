# ADR-001：采用文档驱动 + 总控 Agent 多 Agent 协作治理体系

- **状态**：Accepted
- **日期**：2026-09-08
- **提出者**：Project Master（用户提供方法论规范后落实）
- **关联**：`docs/INDEX.md`、`docs/AGENT_GUIDE.md`、`docs/DEVELOPMENT_GUIDE.md`、`docs/ID_GOVERNANCE.md`

## Context

本项目将采用「人决策 + 多 Agent 长期协作」的开发模式，且项目规模可能持续增长。若使用「想到功能直接编码、遇到问题再改、最后补文档」的传统方式，代码/知识将随规模增长迅速失去可理解性，Agent 需要扫描全项目才能工作，模块间将产生隐式依赖与越权修改。

## Problem

如何让一个由多个 Agent 长期共同开发的软件系统保持：可理解、可协作、可追踪、可测试、可扩展、可审计、可维护、可演进？如何让新增 Agent 无需阅读全部代码即可局部开发？

## Options

| 方案 | 说明 |
| --- | --- |
| A. 无治理、直接编码 | 开发最快，但随规模增长可理解性崩溃，Agent 协作靠全局扫描 |
| B. 单一大 README + 少量文档 | 中心文档膨胀、多事实副本、漂移严重 |
| C. 集中式详尽设计文档（一次性写完） | 与代码脱节快、更新成本高 |
| D. **文档驱动 + 分层知识 + Registry 导航 + Contract 协作 + 变更治理**（采用） | 以 docs/ 分层文档为长期记忆；索引→摘要→契约→代码按需加载；ID 与 Registry 保证可追踪；CR/ACR 通道约束越权 |

## Decision

采用方案 D，落实为本文档体系：

- 知识分层 L0~L8（`PROJECT`/`ARCHITECTURE`/Domain/Module/API/Data/File/Method/Change）
- 全部重要实体分配唯一 ID（`ID_GOVERNANCE.md`），由 Registry 登记导航
- 模块黑盒化，仅通过 Contract/API/DTO/Event 协作
- Agent 分级权限（Read/Write/Review/Request），越权走 CR/ACR 流程
- 文档一致性强制要求（代码 = 文档），Single Source of Truth + 引用替代复制
- Definition of Done + 总控验收（APPROVED / CHANGES_REQUIRED）

## Reason

- 文档作为 Agent 长期记忆，随规模增长保持系统可恢复性（符合用户方法论最高原则）
- 结构化知识代替项目扫描，避免 Agent 每次全量加载
- 唯一 ID + Registry 代替全局搜索，保证可追踪
- 分层渐进落地：本轮先建元治理层 + 项目级骨架，模块级知识在模块划分时生成，避免空模板噪声

## Consequences

### 正面

- 新增 Agent/开发者可经 `INDEX → Summary → Contract → Code` 快速进入
- 变更可追踪、越权可控、知识单一来源

### 代价 / 需注意

- 文档维护成本高于"裸编码"，必须把文档更新纳入 Definition of Done
- 文档与代码一致需要纪律；出现不一致须优先修复（风险登记于 `PROJECT_STATUS.md` 与未来 `RISK_REGISTER.md`）
- ID 唯一性与引用完整性暂时靠规范与审查保障（见 `ASSUMPTIONS.md` ASM-005），规模增大后再评估脚本化
