# ADR-003：AI 评价边界与原则

- **状态**：Accepted
- **日期**：2026-09-08
- **提出者**：Project Master（依据用户「V1 MVP 总控 Agent 指令」§六/§七/§八/§十/§十一）
- **关联**：REQ-005/REQ-006/REQ-008、`docs/ARCHITECTURE.md`

## Context

AI 评价对象是未成年学生的作业。若 AI 输出主观标签（敷衍/学习态度差/能力差）或武断强制重写，将造成体验与信任问题，且无法追溯。需求指令对此有明确原则。

## Problem

如何在 V1 把"AI 不武断评价"从口号落实为可执行、可验证的约束？

## Options

| 方案 | 说明 |
| --- | --- |
| A. 依赖 LLM 自由发挥 | 输出不可控、易贴标签，不可接受 |
| B. 强规则文案模板 | 太僵硬，无法覆盖多样作业 |
| C. 原则固化 + Prompt 资产 + 规则后校验 + 全链路可追溯（采用） | 分层保障 |

## Decision

- **可观察行为表述**：禁止输出"态度/认真/懒惰/能力"等主观结论；只描述可观察表现（如：缺少解题过程、连续漏答、书写清晰度下降），并尽量给出 判断结果 + 依据 + 置信度
- **分级重写建议**：无需重写 / 建议订正 / 建议重写部分题目 / 建议重新完成本项作业；禁止仅凭单次 AI 判断强制重写
- **评分语义**：V1 评分仅代表「今日作业完成质量」，不得解释为学习能力；评分维度与权重（完成度25/正确度30/完整度15/规范度10/书写质量10/作业完成质量10）**配置化，不硬编码**
- **不猜原则**：无法可靠判断时允许"无法判断"，进入人工确认或重新拍摄流程
- **可追溯**：任何评价可回溯 原始图片→预处理→OCR→AI 输入→Prompt 版本→AI 输出→规则处理→最终评价（Prompt 集中管理并版本化，禁止散落代码）
- **落地机制**：上述原则写入 REQ-008 横切约束，成为各模块（M003/M005/M006 等）DoD 审查项与测试用例

## Reason

- 让 AI 输出可观察、可解释、可追责，保护未成年用户体验并满足质量要求（指令 §六/§七/§十一）
- 配置化与版本化支撑 V2 演进而不改核心逻辑

## Consequences

- M005/M006 需设计"Prompt 资产 + 规则后处理"两段式；M003/M005/M006 的 AI 调用统一走 Provider 抽象并记录调用日志（DATA-009）
- 测试用例需包含：主观标签禁用、分级建议边界、无法判断路径、权重配置生效
- Prompt 与评分规则在模块文档中登记为独立资产（模块十二项交付物含 AI Prompt）
