# ADR-005：V1 用户与身份模型 —— 纯家庭模式（PD-004）

- **状态**：Accepted
- **日期**：2026-09-08
- **决定者**：用户（PD-004 确认）+ Project Master
- **关联**：`docs/PROJECT_STATUS.md`（PD-004）、`docs/DATA_MODEL.md`（DATA-002）、`docs/ARCHITECTURE.md` 安全边界

## Context

需求业务流含"教师创建任务 / 学生上传 / 家长查看报告"等角色用语，但 V1 显式禁止班级/学校管理、复杂教师平台、多租户。需要在"有真实账号可隔离数据"与"不重造角色权限体系"之间定边界（PD-004）。

## Problem

V1 采用什么身份模型？教师/学生/家长角色在 V1 如何落地？

## Options

| 方案 | 说明 |
| --- | --- |
| A. 双角色轻量账号（教师 + 家庭） | 更接近需求字面，但教师实体在单家庭使用场景下无实际意义 |
| B. 无账号 + 预置演示数据 | 验证闭环最快，但与"真实用户完成一次评价"验收有差距 |
| C. **纯家庭模式：家庭账号（家长）下挂学生档案** | 家长即布置者与查看者，学生档案为评定对象，最简且真实（**采用**） |
| D. 三角色完整鉴权 | 超出 V1 边界，与"禁止复杂教师平台/多租户"冲突 |

## Decision

- V1 只有两类身份对象：
  - **家庭账号**：注册即用，一个家庭一个空间；家庭内的使用者（家长/监护人）承担需求语境中"教师"的**布置作业**职责，以及查看报告职责
  - **学生档案**：隶属于家庭账号，可多名；为评定对象（对应需求语境"学生"）
- 数据隔离：所有业务数据归属 `family_id`（+必要时 `student_id`），API 仅允许读写本人家庭的档案数据
- 无教师账号、无班级/学校/审批/权限矩阵；登录认证 + 家庭级数据过滤即为全部授权模型
- 语义映射（偏离已获用户确认）：需求"教师创建作业任务"→ 家庭账号家长布置；"学生上传"→ 为该家庭指定学生档案上传
- 未来引入真实教师/班级体系时按扩展点升级（见 ADR-002 扩展预留原则），不阻断数据模型演进

## Reason

- 纯家庭模式是"真实可运行 + 数据隔离 + 最简实现"的最优交点：无需空转的教师实体，也避免无账号的验收失真
- 与 V1"面向真实家长用户的单家庭每日作业评定"使用场景一致

## Consequences

- DATA-002 收敛为：家庭账号（登录凭证/名称）+ 学生档案（姓名/年级等，归属家庭），见 `DATA_MODEL.md`
- 全部 API 鉴权 = 登录态 + 家庭（+学生）数据过滤；`family_id`/`student_id` 进入全部业务数据归属字段
- M001 任务创建者为家庭账号；任务与学生的关系为本家庭内关联

> 澄清（2026-09-08，ADR-008）：本 ADR"无学校"指**无学校账号与学校域管理**（学校管理模块仍禁止，ADR-002）；学生档案关联的"学校基础字典"（DATA-011）为全局共享只读公共数据、由 seed 预置、不带 `family_id`，是家庭数据隔离的**限定例外**，不属学校管理域。
