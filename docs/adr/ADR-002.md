# ADR-002：V1 范围控制（仅 7 模块闭环）

- **状态**：Accepted
- **日期**：2026-09-08
- **提出者**：Project Master（依据用户「V1 MVP 总控 Agent 指令」§二/§十六）
- **关联**：`docs/PROJECT.md`、`docs/MODULE_REGISTRY.md`、`docs/REQUIREMENTS.md`

## Context

用户给出 V1 唯一目标：可真实运行的"AI 每日作业智能评定系统"。同时明示禁止提前开发知识图谱、长期学习画像、自动组卷、个性化训练、阶段测评、学校管理、班级管理、复杂教师平台、多租户等。

## Problem

如何保证 V1 范围不蔓延？未来功能的数据支持如何在"不提前实现"的前提下预留？

## Options

| 方案 | 说明 |
| --- | --- |
| A. 一次性实现全平台功能 | 违反 V1 目标与完成标准，质量不可控 |
| B. 严格限定 7 模块 + 显式禁止项 + 仅数据/边界预留 | 闭环先可用，再谈智能（采用） |
| C. 隐含未来需求随意预留 | 预留无边界 = 隐式实现 V2+，同样蔓延 |

## Decision

- V1 只实现 7 模块闭环：M001 作业任务管理、M002 作业图片采集、M003 AI 作业识别、M004 作业任务匹配、M005 AI 作业质量评价、M006 AI 教师评价与改进建议、M007 今日作业综合报告
- 开发顺序强制：M001→M002→M003→M004→M005→M006→M007→全系统回归；前序未验收（PM `APPROVED`）不得进入下一核心模块
- 显式禁止项（见 `PROJECT.md`）形成硬边界：新模块/新功能必须走变更流程，PM 与用户共同批准
- 未来功能只允许：扩展字段（如实体中预留通用属性位）、扩展接口（模块 API 版本兼容）、扩展模块边界（文档中登记扩展点）——不允许提前实现行为
- 每次模块文档交付包含"后续扩展点"清单（用户指令 §十三），用于沉淀而非实现 V2+ 需求

## Reason

- "当前版本只解决当前版本的问题"；先让核心闭环真实可用，再增加智能能力（指令 §十六）
- 可独立运行与验证是每个版本的最低要求；范围蔓延会破坏该要求（RISK-005）

## Consequences

- 7 模块登记为 Planned，任何新增模块超出 V1 均需变更流程
- 验收含"无越权修改 / 无未契约接口 / 无提前实现 V2+ 功能"
- 报告等输出明确"仅代表今日完成质量"语义，杜绝被误读为画像能力
