# ADR-011：AI Provider 接入策略 —— 真实三方默认，Mock 降级为测试桩/离线（取代 ADR-007，PD-019）

- **状态**：**Accepted**（2026-09-08，随 ACR-002 批准生效；ADR-007 → Superseded）
- **日期**：2026-09-08
- **决定者**：用户（grill 定稿 g3）+ Project Master
- **关联**：`docs/PROJECT_STATUS.md`（PD-019）、`docs/changes/ACR-002.md`、`docs/ARCHITECTURE.md`（AI Provider 抽象层）、`docs/DATA_MODEL.md`（DATA-009）、`docs/ASSUMPTIONS.md`（ASM-010 修订）、`docs/ROADMAP.md`（横切能力）

## Context

用户需求⑤明示"上述提到的大模型均对接第三方模型"，grill g3 定稿：**真实三方为默认运行**。原 ADR-007（抽象 + Mock 先行：默认实现为内置 Mock、真实三方后补）与需求⑤冲突；Mock 应降级为测试桩与离线降级，而非默认运行路径。

## Problem

在"真实三方为默认"下，如何保持 Provider 抽象（可替换/不绑定/可追溯）且不因外部不可用而阻塞开发测试？

## Options

| 方案 | 说明 |
| --- | --- |
| A. 抽象 + Mock 先行（原 ADR-007） | 默认跑 Mock，与需求⑤"对接第三方模型"字面不符 |
| B. **真实三方默认 + Mock 降级**（采用） | Provider 抽象保留；**默认运行 = 真实三方**（OCR/Vision/LLM）；Mock 仅用于测试桩与离线降级（无网/降级时显著标注 `mock-*`） |
| C. 本地开源模型 | 离线但部署重，且非"第三方对接" |

## Decision

- 固定三类 Provider 抽象不变（Vision / OCR / LLM），业务只面向接口，调用统一写 DATA-009（model/prompt_version/request_id/input_ref/latency/token_usage/result/confidence/error；Mock 以 `mock-*` 命名）
- **默认实现 = 真实三方 Provider**：接入通过 配置（密钥/模型/限额）+ Provider 实现类切换；首次接入登记 `EXTERNAL_SYSTEMS.md`；配置项登记 `CONFIGURATION.md`
- **Mock 降级为测试桩与离线降级**：无外部依赖时（离线/密钥缺失/限流降级策略触发）可运行，输出确定性便于单测与验收断言；产物必须标识 Mock 来源，禁止静默冒充真实结果
- **部署环境假设（ASM-010 修订）**：默认部署需**可访问三方 API（联网）**；如目标环境无外网，由配置显式切 Mock 并提示演示/降级语义
- 运行可靠性：真实三方调用需超时/重试/错误映射/限额预算，避免家庭低并发场景下链路不可用

## Reason

- 满足需求⑤："大模型均对接第三方模型"成为默认运行事实而非后补选项
- 抽象/可追溯/单模型不绑定目标不受影响（变化只发生在 Provider 实现层与配置）
- 保留 Mock 测试桩可维持单元测试确定性 + 离线降级兜底，不阻塞 CI

## Consequences

- ADR-007 **Superseded**（抽象层设计继承，仅默认运行策略反转）
- ASM-010 修订为联网前提；RISK-004（照片出域至三方、未成年人数据合规）升级关注、RISK 增补真实三方依赖项（外网/密钥/限额/超时）
- 开发/演示需准备真实三方账号与密钥；`EXTERNAL_SYSTEMS.md`/`CONFIGURATION.md` 随首个真实接入创建
