# ADR-004：V1 技术栈与平台形态（PD-003）

- **状态**：Accepted
- **日期**：2026-09-08
- **决定者**：用户（PD-003 确认）+ Project Master
- **关联**：`docs/PROJECT_STATUS.md`（PD-003）、`docs/ARCHITECTURE.md`、`docs/DATA_MODEL.md`

## Context

V1 验收要求"真实用户完成一次完整作业评价"，且每版本可独立运行验证。使用端需覆盖作业拍照上传与报告查看，后端需能本地单机真实跑通。当时技术栈/平台形态/存储全部未定（PD-003），是进入编码前第一阻塞。

## Problem

选择哪套技术栈与使用端形态，才能做到"最快真实可用 + 可演进"，并支撑 M001→M007 的逐模块验收？

## Options

| 方案 | 说明 |
| --- | --- |
| A. 移动 H5 + Python FastAPI + SQLite 单体 | 浏览器即用（手机/平板/桌面），拍照走浏览器相机；后端单进程提供 API+H5+图片静态服务；SQLite 零运维（采用） |
| B. 微信小程序 + FastAPI | 贴近家长使用习惯，但需小程序账号/资质/开发者工具，构建调试链长，本地验证成本高 |
| C. Web 管理后台 + Java Spring Boot + MySQL | 偏教师管理平台风格，弱化拍照上传场景，开发节奏重 |

## Decision

- **使用端形态**：移动优先响应式 H5（Web），在手机/平板/桌面浏览器均可使用；作业拍照经浏览器 `input capture` 相机能力采集（不引入小程序/原生 App）
- **后端**：Python **FastAPI** 单体应用；同一进程提供 HTTP API、H5 静态资源、本地图片文件服务
- **存储**：**SQLite**（单文件）起步；图片文件存**本地受控目录**；存储访问经统一抽象保留平滑迁移 PostgreSQL / 对象存储的可能
- AI 访问走 HTTP Provider 抽象（见 ADR-007），与业务解耦

## Reason

- "浏览器即用"免去小程序资质/审核与 App 分发的构建链，是本地/局域网真实验证的最短路径
- 单体单进程符合"不做微服务拆分"约束；SQLite 满足单家庭低并发场景，备份 = 库文件 + 图片目录，运维最简
- FastAPI + Pydantic 便于契约式 API 设计与逐模块验收；H5 形态后续可平滑演进为小程序（API 不变，仅表现层换壳）

## Consequences

- M002 需处理浏览器相机兼容差异与图片体积控制（压缩/预览/重拍引导）
- SQLite 写并发受限——V1 家庭场景可接受；并发写入增长前通过存储抽象评估迁移
- 图片本地存储与未成年人照片敏感性并存，安全边界（访问受控、加密要求、审计）按 DATA-003 高敏感落实（见 ARCHITECTURE 安全边界与 ASM-010）
