# ADR-014：V1 范围收窄与横切 AI 接入层执行方（M003/M004 职责吸收 · M005~M007 及 REQ-005~007 后置 V2 · 新增 AGENT-AI）

- **状态**：**Accepted**（2026-09-10，用户就 `CHANGE-003` §6 阻塞项 Q1~Q3 逐项拍板）
- **日期**：2026-09-10
- **决定者**：用户（逐项确认）＋ Project Master
- **关联**：`docs/changes/CHANGE-003.md`（§6 阻塞项，本次决议关闭）、`docs/requirements/CLARIFICATION-2026-09-10.md`（§2.D5/D6、§4.1、§4.2、§5）、`docs/requirements/REQ-010.md`（待确认项处）、`docs/adr/ADR-013.md`（双层模型）、`docs/adr/ADR-002.md`（V1 范围控制）、`docs/adr/ADR-011.md`（Provider 真实三方默认）、`docs/MODULE_REGISTRY.md`、`docs/AGENT_REGISTRY.md`、`docs/ROADMAP.md`、`docs/agents/Task-006.md`

## Context

`CLARIFICATION-2026-09-10.md`（CR-003 / ADR-013）已把作业评定重构为双层模型，并明确两条链路归属：

- **链路 T（任务输入源 → AI 解析 → 任务草稿）→ M001**
- **链路 H（作业照片 → AI 挂接建议 → 逐张复核 → 窗口级门控 → 完成分析）→ M002**

由此 `CHANGE-003` §6 暴露四项未决问题，**阻塞契约评审闭合**（② 阶段无法界定 M003~M007 的修订边界）：

1. **Q1**：M003（AI 作业识别）/ M004（作业任务匹配）的职责是否已被 M001 / M002 + `app/core/ai/` 吸收？
2. **Q2**：`REQ-005`（六维评分）/ `REQ-006`（评语）/ `REQ-007`（报告）是否仍在 V1 必做范围？——`CLARIFICATION` §4.1 必做 10 项与 §5 验收剧本 7 条**均未列**，§4.2「不做」列出「**评估报告 / 汇总简报**」。
3. **Q3**：横切层 `app/core/ai/`（Provider 抽象 + prompt 管理 + 结果 schema 校验 + 降级）的执行方。
4. **Q4**：`Task-002`（AGENT-M002 正按 M002 契约 v0.3.0 编码）的去留。

## Problem

在同一份需求基线（`REQ-001`~`REQ-010` 均 Approved）下，存在两种自洽解读，必须显式拍板，否则契约边界无法闭合：

- **解读 A（维持原状）**：M003~M007 全部按序实现，V1 = 7 模块闭环（ADR-002 原口径）。
- **解读 B（随 CR-003 收窄）**：链路 T/H 的 AI 能力已被 M001/M002 承载，V1 = 「采集 → 挂接 → 聚合子任务级完成判定 → 前端」闭环（即 `CLARIFICATION` §4.1 十项 + §5 剧本 7 条），M003~M007 后置。

同时，横切 AI 接入层若由业务模块 Agent 分担实现，将违背 ADR-011「统一 Provider 抽象 + 统一调用记录」的意图，产生实现分裂。

## Options

**Q1 —— M003~M007 的 V1 职责边界**

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 全部保留独立模块 | M003~M007 回到原计划按序实现 | ❌ 与 §4.1/§5 范围不一致；M003/M004 与 M001/M002 职责重复，边界无法划清 |
| B. **M003/M004 吸收，M005~M007 保留登记**（采用） | M003/M004 职责并入 M001（链路 T）/ M002（链路 H）；**Module ID 保留不撤销**，状态标 Deferred；M005~M007 状态随 Q2 定 | ✅ 自洽；不消耗 ID；不撤销已登记模块 |
| C. 全部 V1 不实现 | V1 仅 M001 + M002 + 共享层 | ⚠️ 表述上与 B 结果接近，但抹平了「M005~M007 待 V2 回归」的可追踪性，不采用 |
| D. M003/M004 合并为新模块 | 新设「作业智能判定」模块（需新 Module ID） | ❌ 净增一个 V1 内空壳模块，无实现载体（能力已落 M001/M002） |

**Q2 —— REQ-005~007 是否 V1 必做**

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 全部保持 V1 必做 | 维持 P0，V1 扩至评分 + 评语 + 报告 | ❌ 与 §4.1 十项 / §5 剧本 7 条冲突（二者均未含），需反向扩写权威源 |
| B. **全部后置 V2**（采用） | V1 = §4.1 十项闭环；`REQ-005`~`REQ-007` 状态改 **Deferred**（需求单保留，不作废） | ✅ 与 §4.1/§4.2/§5 逐条一致；V1 范围与验收剧本完全同构 |
| C. 部分保留（如仅六维评分） | V1 保留评分、评语与报告后置 | ❌ 会形成"评分无报告出口"的半闭环，且 §5 剧本仍未覆盖 |

**Q3 —— `app/core/ai/` 执行方**

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. **新增 `AGENT-AI`（Task-006）**（采用） | 横切能力独立 Agent，写区仅 `backend/app/core/ai/**` | ✅ 边界最清晰，符合 ADR-011 统一接入意图 |
| B. AGENT-M001 承担 | 由基座模块 Agent 承担 | ❌ 易与 M001 业务代码耦合，弱化"共享基础设施"定位 |
| C. AGENT-M002 承担 | 由挂接/分析首个调用方承担 | ❌ 同上；且 M002 侧工作量大（v0.4.0 改接） |
| D. 按链路分担（T→M001 / H→M002） | 分工更贴近调用方 | ❌ 共享层被两份实现切分，存在实现分裂风险 |

## Decision

1. **Q1：M003 / M004 的 V1 职责被吸收，Module ID 保留不撤销。**
   - `M003`（AI 作业识别）：职责并入 **M001**（链路 T 任务解析）+ **M002**（链路 H 挂接建议）+ 横切 `app/core/ai/`；`MODULE_REGISTRY.md` 状态 → **Deferred**。
   - `M004`（作业任务匹配）：职责并入 **M002**（聚合子任务级完成结论生成）；状态 → **Deferred**。
   - `M005` / `M006` / `M007`：**登记保留**，状态随第 2 条定为 **Deferred（V2）**。
   - `AGENT-M003`~`AGENT-M007` 在 V1 生命周期内**不启用**（登记为 Inactive），V2 回归时重新评估。
2. **Q2：`REQ-005`（六维评分）/ `REQ-006`（评语）/ `REQ-007`（报告）后置 V2。**
   - 三张需求单**保留、不作废**，状态由 Approved 改为 **Deferred**；其 V1 输入口径修正（聚合子任务级结论）继续有效，作为 V2 回归基线。
   - V1 范围以 `CLARIFICATION` §4.1 **必做 10 项** 为唯一清单，验收以 §5 **剧本 7 条**为唯一剧本。
   - 对应实现载体 `M005` / `M006` / `M007` 契约轮**不在 CHANGE-003 内启动**。
3. **Q3：横切 AI 接入层执行方 = 新增 `AGENT-AI`（任务书 `docs/agents/Task-006.md`）。**
   - 写区 = `backend/app/core/ai/**`（Provider 抽象 Vision/OCR/LLM + prompt 版本管理 + 结果 schema 校验 + 降级）+ 配套测试；承接 `ADR-011` 与 DATA-009 统一调用记录。
   - **不设业务 Module ID**（保持"共享/基础设施"定位）；**禁止**改业务模块代码与任何模块契约文档。
4. **与 ADR-002 的关系（范围控制解释，非豁免）**：本次是**经用户批准的显式范围收窄**（走 CR/CHANGE 流程），**不是**新模块或隐式实现 V2+：
   - `MODULE_REGISTRY.md` 仍登记 **M001~M007 七个 Module ID**，**未新增第 8 个业务模块**（`AGENT-AI` 是 Agent 角色，不是模块）；
   - ADR-002「禁止提前实现 V2+」与「显式禁止项」**继续适用**；M005~M007 后置期间**不得**实现其行为（仅保留字段/接口与文档登记）。
5. **Q4（执行治理，非架构决策）**：`Task-002` 采用 **部分冻结 + 契约定稿后增量改接**——保留已交付成果，冻结「归属/挂接」相关段，允许收尾与 CR-003 无关段（质检/归一/受控存储/受控取图/双主体 API）；`Task-005` 定稿（M002 v0.4.0）后按新契约**增量改接**，返工面限于归属段。落库见 `docs/agents/Task-002.md` + `PROJECT_STATUS.md` PD-029。

## Reason

- 与 `CLARIFICATION` §4.1（必做 10 项）/**§4.2（不做：评估报告 / 汇总简报）**/§5（剧本 7 条）逐条同构，V1 范围与验收标准一次性对齐，消除"需求说做、剧本不测"的缺口。
- 消除 M001/M002 与 M003/M004 的**双重归属**：`D5` 已把两条链路定在 M001/M002，若再开 M003/M004，同一能力将出现两处契约与两处实现。
- Module ID 保留 + 状态 Deferred，满足 `ID_GOVERNANCE.md`「ID 不复用、不撤销」要求，V2 回归可直接复用编号，无需重新分配。
- 横切层独立 Agent 是唯一能同时满足"ADR-011 统一抽象""不塞进业务模块（`CLARIFICATION` §2.D4）"两项约束的方案。

## Consequences

- **`CHANGE-003` §6 四项阻塞全部关闭**：② 契约修订评审（Task-004 / Task-005）的边界自此闭合，可提交 PM 复核。
- **`MODULE_REGISTRY.md`**：M003/M004 → Deferred（职责吸收）；M005~M007 → Deferred（V2）；共享基础设施 `app/core/ai/` 执行方 = `AGENT-AI`。
- **`AGENT_REGISTRY.md`**：新增 `AGENT-AI`（Active，Task-006）；`AGENT-M003`~`AGENT-M007` → Inactive（V1 不启用）。
- **`REQUIREMENTS.md` + 单页**：`REQ-003` 承载模块改 M001（链路 T）+ M002（链路 H）；`REQ-004` 承载模块改 M002；`REQ-005`/`REQ-006`/`REQ-007` 状态 → **Deferred（V2）**。
- **`ROADMAP.md`**：功能域 D（综合评判 + 每日报告）与里程碑 **M-D 后置 V2**；V1 主线 = 域 A/B/C + M-END（回归范围收窄为 A/B/C + 剧本 7 条）。
- **`CHANGE-003` §2.3**：横切清单 C1 定稿（执行方 `AGENT-AI`）；§3 增加 `Task-006` 行；§4 DoD 增加"边界决议已落库"。**注意**：`Task-006` 属 ③ 实施阶段，**启动前置 = ② 复核 APPROVED**（Contract First）。
- **数据实体不受影响**：`DATA-006/007/008`（质量评价/教师评价/报告）**保留登记**，随 V2 回归启用（V1 不写入）；`DATA-009`（AI 调用记录）由 `AGENT-AI` 在 V1 内落地。
- **风险**：新增 **`RISK-012`**（V1 收窄后 M005~M007 的 V2 回归成本与"综合评定"主题交付面收窄）；`RISK-005`（范围蔓延）缓解增强。
- **V2 回归要求**：回归 M005~M007 时须重新评估本 ADR（届时 `REQ-005`~`REQ-007` 状态由 Deferred 恢复为 Approved/In Progress），并走 CR/变更流程。
