## Context / 问题

Frozen 契约（M002 `MODULE_API.md` §API-M002-007）声明响应：

```json
{ "photo_id": "uuid", "links": [LinkDTO], "suggested_at": "..." }
```

运行时实现（`LinkSuggestionOut`）返回：

```json
{
  "photo_id": "uuid",
  "status": "unassigned|suggested|assigned|rejected",
  "suggestions": [
    { "link_id": "uuid", "group_subject_id": "uuid", "subject": "数学",
      "confidence": 0.87, "source": "ai", "suggested_at": "..." }
  ]
}
```

两处不一致：① 外层键 `links` vs `status` + `suggestions`；② 元素字段（实现逐条给出 `confidence`/`source`/`suggested_at`，契约只给 `LinkDTO` 整体）。

## 变更范围（建议）

`API-M002-007` 响应体修订为**实现现状**：

- `{ "photo_id": "uuid", "status": PhotoStatus, "suggestions": [ { "link_id", "group_subject_id", "subject", "confidence", "source", "suggested_at" } ] }`
- 同步：`docs/modules/M002/MODULE_API.md`（§API-M002-007 响应 + DTO 约定补 `LinkSuggestionItem`）、`docs/API_REGISTRY.md`（`API-M002-007` 备注）。
- 版本：M002 契约 **v0.4.0 → v0.4.1**（**已升版，2026-09-10 Applied**），`MODULE_CHANGELOG.md` 追加记录。

**理由（为何以实现为准，而非改实现回契约）**：

1. `links` 与 `API-M002-003` / `API-M002-005` 的 `links:[LinkDTO]`（**已建立的挂接关系**，含 `confirmed_at`/`rejected_at`）语义冲突；建议（`source=ai` 且未确认）用 `suggestions` 表达更准确，也与 §4.4 挂接语义一致。
2. 实现返回逐条 `confidence` / `suggested_at`，前端「采纳 / 驳回 / 重试建议」界面需要这些字段；改实现回契约会**丢失信息**并引发前端二次返工。
3. 前端 `Task-009` 已按运行实现取用（`LinkSuggestionResult.suggestions`），**当前前后端运行一致**；本 CR 属「文档追平实现」，不阻断任何在途任务。

## 备选方案（如用户不同意）

- **B（改实现回契约）**：`LinkSuggestionOut` 改为 `{photo_id, links, suggested_at}`，元素退回 `LinkDTO`（丢失 `confidence`/`suggested_at` 逐条信息，或需扩展 `LinkDTO` 本身）→ **代价**：后端改动 + 前端 `Task-009` 已交付代码返工（`LinkSuggestionResult` + `PhotoListView` 重试/建议态），且需 `Task-010` 之后追加返工任务。
- **C（不处理）**：保留「契约与实现不一致」，运行一致但契约失真 → **不建议**（违反 `docs/` 为 Single Source of Truth 的治理原则）。
