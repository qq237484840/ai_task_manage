# BUG-004 —— M001 `default_parser` 以位置参数调用 keyword-only 的 `parse_task_spec`，核心 AI 链路被静默降级

- **BUG ID**：BUG-004 ｜ **状态**：**Verified（`Task-012` 修复 + PM 独立复核成立 + `Task-014` 复审在真实装配路径下断言成立，2026-09-10）** ｜ **发现日期**：2026-09-10
- **发现者**：`AGENT-M002`（`m002-dev`，执行 `Task-011` ④ 验收时）
- **修复执行**：**`Task-012`（`AGENT-M001` / `m001-dev`）** ｜ **复核**：Project Master（修复后复审 = `Task-014`）
- **影响范围**：M001 链路 T 任务解析；`app.modules.m001.services.task_parser.default_parser` + `app.core.ai.parse_task_spec`
- **严重级别**：**高**（核心 AI 任务解析入口在真实/Mock 配置下均不可达，`default_parser` 恒回退本地 Mock 兜底，导致文本源无法调用 LLM/Vision，图片源无法 OCR）

## 1. 现象

- 上传任务输入源（图片/文本）后，`tasks.spec_status` 由服务写入 `placeholder`；
- 文本源本应经 `app.core.ai.parse_task_spec` 解析为 `parsed`，图片源在真实 Provider 下应尝试 OCR/Vision，但实际：
  - 文本源得到的是本地启发式 `mock_parse_sources` 结果；
  - 图片源（无文本时）返回 `None`，保持 `placeholder`；
- 链路 T 的核心 AI 解析从未真正执行，依赖本地兜底完成。

## 2. Root Cause

| # | 环节 | 证据 |
| --- | --- | --- |
| 1 | M001 解析入口 = `app.core.ai` 的**模块级便捷函数** | `task_parser.py:112-124` `_ai_parser()` → `getattr(ai, "parse_task_spec")` → `app/core/ai/service.py:556`：`def parse_task_spec(session, **kwargs)` |
| 2 | `default_parser` 以**位置参数**调用，`sources` 被误当 `session` | `backend/app/modules/m001/services/task_parser.py:132`：`coerced = _coerce_draft(parser(sources))` |
| 3 | 方法体要求 `sources` 为 keyword-only，且类型为 `list[SourceInput]` | `backend/app/core/ai/service.py:127-135`：`def parse_task_spec(self, session, *, family_id=None, sources: list[SourceInput], grade_level=None, request_id=None)` → 便捷函数缺 `sources` 关键字 → `TypeError: missing 1 required keyword-only argument: 'sources'` |
| 4 | 抛错被静默吞掉 | `task_parser.py:135`：`except Exception: pass` → 直接落到本地兜底 |
| 5 | 本地兜底无法 OCR 图片 → 图片源保持 `placeholder` | `mock_parse_sources` 中非文本源 `continue`（`task_parser.py`） |

**为何未在 Task-006/007 发现**：M001 自有测试直接断言本地兜底结果（`contents=[...]`），未断言 `spec_status` 是否由 AI 解析生成；Task-006 的 AI 层测试未通过 M001 `default_parser` 的真实调用路径触发。

## 3. Fix（不在本任务执行）

**推荐方案**：将位置调用改为 keyword 调用，并完成 `dict → SourceInput` 转换。

```python
# backend/app/modules/m001/services/task_parser.py:132 附近
from app.core.ai.types import SourceInput

coerced = _coerce_draft(parser(None, sources=[SourceInput(**s) for s in sources]))
```

> 注意两点：① 模块级便捷入口签名为 `parse_task_spec(session, **kwargs)`，位置参数是 `session`，`sources` 必须走关键字；② 方法体要求 `sources: list[SourceInput]`（dataclass），而 M001 当前传入 `list[dict]`，需 `SourceInput` 转换（或由 `_ai_parser()` 返回一个已适配的包装函数）。

**备选方案**：在 `app.core.ai` 侧新增一个接受 `list[dict]` 的便捷入口 `parse_task_spec_from_dicts`，M001 保持不变。需权衡模块间依赖；当前 `task_parser.py` 已有延迟 import，推荐方案更直接。
