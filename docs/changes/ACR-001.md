- **批准者**：用户（2026-09-08 审阅批准）+ Project Master
- **关联**：ADR-009（决策）、CR-001（并行数据面变更）、CR-002/ACR-002（并行内容级重构）、`MODULE_REGISTRY.md`（M001）、`DATA_MODEL.md`（DATA-002）

## 变更类型

架构变更（认证/授权主体模型），影响 **M001（已 Frozen v0.1.1、已实现并验收 Stable）** 与全部下游模块契约的 Security 语义。

## Context / 目标

用户确认 V1 采用"家庭账号（家长）+ 学生子账号"两级主体（ADR-009）：学生独立登录、仅本人数据；家长管理全家并兜底。现状 M001 认证面（`family_accounts`/`auth_sessions` 绑 `family_id`、Bearer → AuthContext 仅 family_id、API-M001-001~012 全部家庭级）无法表达"当前主体是哪个学生"。

## 变更范围（提案）

1. **凭据面**：学生子账号开通/停用（家长操作）；登录名唯一性约束范围 = 家庭内 or 全局（按 M001 登录名规则定）；口令策略复用 M001（scrypt + 爆破退避），学生弱口令提示
2. **会话面**：`auth_sessions` 支持主体类型 `family|student`（student 会话额外绑定 `student_id`）；登出/过期沿用
3. **上下文与鉴权**：shared AuthContext 升级为 subject（type + subject_id），暴露 `family_id`（student 会话经档案反查）与可选 `student_id`；REST 鉴权依赖改为双层过滤：家庭级 + （family 主体可选任意本家 student / student 主体强制本人）
4. **M001 API 受影响**（走 CR 流程冻结面变更）：
   - 新增：学生账号开通/停用/改密、学生登录、主体信息（当前学生档案）
   - 调整：学生档案创建/列表/更新的可见与授权主体描述；任务创建允许 student 主体（仅本人档案，另见 CR-001）
5. **数据迁移**：既有 54 测试回归 + 双主体越权矩阵新增用例；`family_id` 过滤保留为底线
6. **前端**：学生登录入口与会话切换（家长端"当前学生"选择保留，兜底代传路径）

## 不包含（范围外）

- 学生端之外的任何新角色（班级/教师/审批）——ADR-002/ADR-009
- 家长角色内的细粒度权限矩阵

## 验收标准（草案）

- 学生登录后仅能读取/写入本人档案数据（URL 传参他人 → 404）；家长登录可操作全家学生
- 会话/审计记录主体类型与 id；口令策略与越权测试随 M001 回归全绿
- M001 原有 API-M001-001~012 行为对 family 主体向后兼容（不得破坏既有 54 测试语义）
