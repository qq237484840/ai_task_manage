# BUG-009：DATA-009 写失败（锁竞争）导致 Session 中毒 → `API-M002-007` 返回 **500**

- **BUG ID**：BUG-009 ｜ **状态**：**`Confirmed`（未修复）** ｜ **发现日期**：2026-09-17 ｜ **级别**：**高**
- **发现场景**：`CR-006` 子项 B 验收（`Task-025`）**真机**（uvicorn `:8011` + 独立 SQLite 库）——
  上传触发的**后台建议线程**与 `GET /photos/{id}/link-suggestions?retry=true` **并发写** DATA-009。
- **关联**：**`BUG-008`（同一底层成因 = SQLite 锁竞争；本单为其更严重的衍生症状）**、`REQ-008` / **DATA-009**、
  `ADR-011`（真实三方）、`CR-006` 子项 B（本单由该子项验收暴露，但**非其引入**，见 §4 基线对照）

## 1. 现象（原文，真机日志 2026-09-17）

```
sqlalchemy.exc.OperationalError: (sqlite3.OperationalError) database is locked
[SQL: INSERT INTO ai_call_records (call_id, request_id, ... ) VALUES (...)]
...
File "C:\DevProject\AI.TaskManage\backend\app\modules\m002\api\link_routes.py", line 88, in get_link_suggestions
    db.commit()
sqlalchemy.exc.PendingRollbackError: This Session's transaction has been rolled back due to a previous
exception during flush. To begin a new transaction with this Session, first issue Session.rollback().
Original exception was: (sqlite3.OperationalError) database is locked
ERROR:    Exception in ASGI application
```

→ 端点返回 **HTTP 500**：`{"code":"INTERNAL_ERROR","message":"服务器内部错误","request_id":"-"}`

**要点**：AI 调用本身**已到达三方并拿到 503**（`model_not_found`），随后写留痕失败 →
调用方 Session 进入「待回滚」状态 → `retry` 分支的 `db.commit()` 抛 `PendingRollbackError` → **主链路 500**。

## 2. 根因（文件:行）

1. `backend/app/core/ai/records.py:100-104`：`record_call` 的 `except Exception:` 仅
   `logger.warning("AI 调用记录写入失败", exc_info=True)` + `return None`（设计意图「审计写入失败不得中断主链路」正确），
   但**未 `session.rollback()`** —— `session.flush()` 因锁失败后，SQLAlchemy 要求先 `rollback()`，
   否则该 Session 的**后续任何操作**都会抛 `PendingRollbackError`。
2. `backend/app/modules/m002/api/link_routes.py:88`（`retry=true` 分支的 `db.commit()`；**基线代码同位置亦存在**）
   在同一 Session 上继续提交 → `PendingRollbackError` → 未被业务错误处理器覆盖 → **500**。
3. **触发条件 = 并发写同一 SQLite 库**（默认 journal 模式非 WAL）：真机上
   `suggestion_scheduler` 默认 **daemon 后台线程**（上传即触发建议）与同步 `retry` 的 AI 调用**同时**写 `ai_call_records`。

## 3. 影响

- **主链路 500** —— 对 `BUG-008` 原结论「**主链路不受影响**」的**重要修正**：该判断在**并发写**场景下**不成立**（故本单级别定为**高**）。
- **触发面**：上传后**立即**对同照片触发 `retry`（前端「重试建议」入口 / `REQ-011` 卡片），或任何与后台建议并发的 `retry`。
- **数据面**：该次 AI 留痕丢失（= `BUG-008` 原症状）；`CR-006` 子项 B 的 `last_attempt` 此时为 `null`（**降级为「无信息」而非错误信息**，不误导）。

## 4. 复现步骤（确定性，可复现）

**构造**：另开一条 SQLite 连接持有写锁（`BEGIN IMMEDIATE` + 一次 UPDATE）→ 在持锁期间调用
`GET /photos/{id}/link-suggestions?retry=true`。

**原文（2026-09-17，真机 `:8011`，修复版）**：

```
LOCK_HELD
RESP_STATUS=500
RESP_BODY={"code":"INTERNAL_ERROR","message":"服务器内部错误","request_id":"-"}
LOCK_RELEASED
AFTER_UNLOCK_STATUS=200
AFTER_UNLOCK_last_attempt={'code': 'server_error', 'message': '三方服务错误 503 | 三方摘要: model_not_found: ...'}
```

**基线对照（证明非 `CR-006` 子项 B 引入）**：`git stash push -- backend/app/modules/m002/api/link_routes.py backend/app/modules/m002/schemas.py`
（回退本次改动）→ 重启同配置服务 → 同法构造：

```
LOCK_HELD
RESP_STATUS=500
RESP_BODY={"code":"INTERNAL_ERROR","message":"服务器内部错误","request_id":"-"}
```

→ **基线同样 500** = **既有缺陷**（`record_call` 未回滚 + 同 Session 继续 commit，均在本次改动之前）。

## 5. 推荐修复（**须走修复任务书 / CR；本单只登记**）

1. **最小且推荐**：`record_call` 的 `except` 内先 `session.rollback()` 再 warning/计数
   —— 使审计写入失败**不污染调用方事务**（仍属 `app/core/ai/` 写区 → 需 `AGENT-AI` 任务书）；
2. **可观测**（与 `BUG-008` 推荐项合并）：有限重试 + 失败计数/告警（如 `ai_records_dropped`）；
3. 评估 `core/database.py` 启用 **WAL + `busy_timeout`**（全局行为变更，须评估既有并发路径）；
4. 评估 `suggestion_scheduler` 与同步 `retry` 的**同照片互斥/去重**（并发触发只跑一次）。

**契约影响**：无（DATA-009 / `API-M002-007` 字段均不变）。

## 6. 验证要求（修复后）
