# BUG-002 —— `GET /photo-gates` 无法按窗口分组 + 完成分析门控前置失效

- **BUG ID**：BUG-002 ｜ **状态**：**Verified（PM 复核 APPROVED 并关闭，2026-09-10）** ｜ **发现日期**：2026-09-10
- **发现者**：`AGENT-M002`（`m002-dev`，`Task-009` 交付时以 Request-2 上报）｜ **复核确认**：Project Master（独立核实代码链，2026-09-10）
- **修复执行**：`AGENT-M002`（`Task-010`）｜ **写区**：`backend/app/modules/m002/**` + M002 测试
- **影响范围**：M002 `API-M002-008`（门控查询）、`API-M002-009`（完成分析生成前置）、`API-M002-005` 响应中的 `gate` 字段；间接影响 ④ 验收剧本（浏览器级）
- **严重级别**：**高**（窗口级门控是 ADR-013「全部复核后才分析」的强制点；缺陷使其**后端强制完全失效**，仅剩前端禁用提示，非安全边界、可绕过）

## 1. 现象

1. 某学生存在**多个归属窗口**时，`GET /api/v1/photo-gates` 仅返回 **1 条**记录，且 `group_key` 为**空字符串**（跨窗口聚合，违反契约「按窗口返回数组」）。
2. `GET /api/v1/photo-gates?group_key=<真实窗口 key>` 恒返回 `{total_photos: 0, pending_photos: 0, satisfied: true}`。
3. 因此 `POST /api/v1/completion-analyses` 在**照片尚未全部确认挂接**时**不会**返回 `409 gate_not_satisfied`，门控前置形同不存在。

## 2. Root Cause（PM 独立核实链）

| # | 环节 | 证据 |
| --- | --- | --- |
| 1 | M002 消费了**契约外**接口 `get_group_subject` | `docs/modules/M001/MODULE_API.md` §内部服务接口（Frozen v0.2.0）仅登记 `get_student` / `get_task` / `list_tasks` / `resolve_window` / `list_groups` / `get_group` / `ensure_group` / `commit_conclusion` / `migrate_links_hook` / `mark_in_progress` —— **无 `get_group_subject`**；`docs/modules/M002/MODULE_API.md` 亦自述消费面同为上述清单。该方法是 M001 **内部实现细节**（见 `docs/modules/M001/MODULE_CHANGELOG.md` services 方法清单） |
| 2 | 该接口返回的 DTO **不含 group 上下文** | `backend/app/modules/m001/schemas/task_group.py` `TaskGroupSubjectDTO = {group_subject_id, subject, content_refs, conclusion, conclusion_status}`；而 `group_key`/`window_type`/`student_id`/`display_name` 仅在 `TaskGroupDTO` 上 |
| 3 | 网关回填失败 → 空串 | `backend/app/modules/m002/clients/task_client.py:290` `group = getattr(raw, "group", None) or raw` → `TaskGroupSubjectDTO` 无 `group` 属性 → `group = raw` → `_to_subject_ref(raw, raw)` → `group_key`/`window_type`/`student_id` 全为 `""` |
| 4 | 门控按 `group_key` 分桶 → 全部落空串 | `backend/app/modules/m002/services/gate_service.py:61-69` `windows.setdefault(ref.group_key, ...)` |
| 5 | 单窗口查询恒不匹配 → `409` 不可达 | `gate_service.py:73` `if group_key is not None and key != group_key: continue` → `""` != 真实 key → 结果空 → `get_gate` 兜底返回 `satisfied=True(total=0)`（`gate_service.py:106-114`）→ `AnalysisService._require_gate`（`analysis_service.py:157-169`）永不触发 `GateNotSatisfiedError` |

**为何未被既有测试发现**：`Task-008` 的 M002 单测使用 `FakeGateway` 桩（注入完整的 `GroupSubjectRef`），**未覆盖真机 M001 DTO**；契约消费面与 M001 实现之间的这一缺口无集成用例守护。

## 3. Fix（Task-010，不在本文件执行）

1. **默认路径改走契约内接口**：`DefaultM001Gateway` 必须经 `list_groups(session, family_id)` / `get_group(session, family_id, group_id)` 定位 `group_subject_id` 对应聚合对象，从而**回填 `group_key` / `window_type` / `student_id` / `group_id`**（`TaskGroupDTO` 已含这些字段）。
2. 如保留 `get_group_subject` 作为加速路径，**必须**在拿到 subject 后补齐 group 上下文；并在注释中标注「非契约实现细节，仅作加速，缺失时回落契约路径」。
3. 补**真机 M001↔M002 集成用例**（不使用 `FakeGateway` 桩）：多窗口分组 / `409 gate_not_satisfied` 可达 / 全部确认后 `200`。

**M001 侧零改动、无需契约变更**（缺口在 M002 消费适配侧）。

## 4. 临时缓解（前端，`Task-009` 已交付）

`frontend/src/views/PhotoListView.vue` `localGate()` 本地重算门控，使「待复核 N 张 / 未满足禁用生成」UI 表现正确 —— **仅为展示层兜底，不构成强制**，不得据此关闭本 BUG。
