# BUG-008：DATA-009（AI 调用记录）在 SQLite 锁竞争下**静默丢失**

- **BUG ID**：BUG-008 ｜ **状态**：**`Confirmed`（未修复）** ｜ **发现日期**：2026-09-16 ｜ **级别**：**中**
- **发现场景**：`CR-006` 子项 A 实施（`Task-022`）**迁移重建库**时执行 `start_server.ps1 -Seed`（`.e2e/seed.py`），
  服务与种子脚本**同时写同一 `acceptance.db`** → 真实 AI 调用**返回 200**，但记录写入失败。
- **关联**：`REQ-008` / **DATA-009**（可追溯链）、`ADR-011`（真实三方）、`BUG-005`（同为「留痕失真」主题，但成因不同）

## 1. 现象（原文）

```
2026-09-16 23:09:44 INFO httpx HTTP Request: POST https://www.hhhana.lol/v1/chat/completions "HTTP/1.1 200 OK"
2026-09-16 23:09:49 WARNING uvicorn.error AI 调用记录写入失败
Traceback (most recent call last):
  ...
sqlite3.OperationalError: database is locked
```

**要点**：AI 调用**成功**（HTTP 200）→ 但 **DATA-009 无该次记录**（`record_call` 返回 `None`），
调用方**仅见 warning**，**主链路照常成功**（照片上传/建议流程未受影响，实测 `201` + 列表 200）。

## 2. 根因（文件:行）

- `backend/app/core/ai/records.py:100-104`：`record_call` 以 `except Exception:` 兜底 ——
  「审计写入失败不得中断主链路」（**设计意图正确**），但**只记 warning 并 `return None`**，
  **无重试、无计数、无补偿**，调用方也无从得知「本次未留痕」。
- 底层成因：**SQLite 单写者**。`session.flush()` 遇到另一连接持写锁 → `database is locked`
  （pysqlite 默认 `timeout=5s`，超时即抛）。种子脚本 + 运行中服务的**并发写**是本次直接触发条件。

## 3. 影响

- **可追溯性缺口**：DATA-009 是「证明 AI 真跑」的权威证据（`Task-021` 即依据 `mock=0/status=ok` 判定）；
  记录丢失会**直接削弱**验收/排障的可信度，且**表面上无任何异常**（UI、日志均正常）。
- **不可观测**：丢失只出现在服务 warning 日志中，**无指标/无告警**，运维与 PM 均难察觉。
- **不影响业务正确性**：主链路（上传、解析、挂接）按设计不受影响 —— 这也是缺陷级别定为**中**而非高的原因。

## 4. 复现步骤（可复现命令）

```powershell
# 服务与种子脚本并发写同一库（现状即如此：seed.py 经 TestClient 调用同一 .env 的 acceptance.db）
powershell -NoProfile -ExecutionPolicy Bypass -Command "& 'c:\DevProject\AI.TaskManage\start_server.ps1' -Seed"
# 观察 at_server.err.log / 控制台：出现 "AI 调用记录写入失败" + sqlite3.OperationalError: database is locked
```

## 5. 推荐修复（**须走 CR 或修复任务书，本单只登记**）

1. **推荐**：`record_call` 失败**有限重试**（短退避 2~3 次）+ 仍失败则**计入可观测计数**
   （如 `logger.error` + 健康检查字段 `ai_records_dropped`），使「留痕缺失」**可被发现**；
2. 或：SQLite 侧启用 **WAL + `busy_timeout`**（`core/database.py` 连接参数），降低锁冲突概率
   （**注意**：这是全局行为变更，需评估对既有并发路径的影响）；
3. 或：把 DATA-009 写入移出业务事务（独立短事务）—— 与「复用调用方 Session」的既有设计冲突，**须 CR 评估**。

**契约影响**：无（DATA-009 字段不变）；**须补**「记录写入失败时的可观测契约」（超出既有契约文本）。

## 6. 验证要求（修复后）

- 判别力：构造锁竞争（并发写）→ 断言**不再静默丢失**（重试成功或计数可见）；**红→绿**原文必附；
- 全量回归用例数不减；`records.py` 改动须覆盖既有 DATA-009 用例（`tests/unit/test_ai_records.py` 等）。
