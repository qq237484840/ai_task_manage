# BUG-005 —— 三方错误分类与留痕失真：403「余额/配额不足」被误报为鉴权失败，且三方响应体被丢弃不可排障

- **BUG ID**：BUG-005 ｜ **状态**：**`Fixed`（2026-09-14，`Task-015` 修复；全量回归 251/0/0/0 + 红→绿 + 写区双证）** ｜ **发现日期**：2026-09-14
- **发现者**：Project Master（真实三方 AI 联调取证，`starsea` OpenAI 兼容中转）
- **影响范围**：`backend/app/core/ai/errors.py::from_http_status` + DATA-009 `ai_call_records.error`
- **严重级别**：**中**（不改变「调用失败即降级」的行为，但使线上故障**不可快速定位**，且 DATA-009 留痕失真 —— 与 `Task-006` §3.1「返回明确不可用信号」的意图不符）

## 1. 现象（2026-09-14 实测原文）

1. 三方因**账户余额不足**返回 `HTTP 403`，响应体为：

   ```
   {"error":{"code":"pre_consume_token_quota_failed",
             "message":"您的 API Key 余额不足：剩余 ¥0.005557，本次请求预估需 ¥0.010639…"}}
   ```

   系统侧记录（DATA-009 `ai_call_records.error` 原文）却是：

   ```
   {"code": "auth_error", "message": "三方鉴权失败"}
   ```

2. 同一时刻、同一密钥、同一 `base_url` 的**直连请求返回 200** → 按记录中的「鉴权失败」去排查会被引向**错误方向**（密钥错误 / URL 拼接错误 / env 覆盖 / 代理注入），本次排查耗费多轮脚本才定位真实原因（配额不足）。
3. `from_http_status(status_code, body)` 虽接收 `body`，但在 401/403/429/5xx 分支**完全不使用**：所有 message 为固定文案，三方返回的真实原因被丢弃。

## 2. Root Cause

| # | 环节 | 证据（`errors.py`） |
| --- | --- | --- |
| 1 | **403 无条件映射为 `AUTH_ERROR`** | `:67-68` `if status_code in (401, 403): return AIError(AIErrorCode.AUTH_ERROR, "三方鉴权失败", ...)` —— 未区分「密钥无效」与「账户余额/配额不足」（后者在 OpenAI 兼容生态普遍复用 403 + `insufficient_quota` / 厂商自定义 code） |
| 2 | **`body` 仅被 400/422 内容安全分支使用，其余分支丢弃** | `:66` `text = (body or "").lower()` 只在 `:71-74`（`400/422` 且命中 `content`/`policy`/`safety`/`refus`/`moderation`）参与判定；`:68/:70/:76/:78` 四个分支的 message 均为常量 |
| 3 | `AUTH_ERROR` **不可重试** → 配额场景下不重试（方向性浪费被抑制，但留痕仍错） | `:27-34` `RETRYABLE_CODES` 不含 `AUTH_ERROR`；`core/ai/service.py:135` 依 `retryable` 决定是否重试 |
| 4 | DATA-009 仅落 `as_dict()`（`code` + `message`）→ 无三方响应摘要 | `AIError.as_dict()` `:59-61`；`core/ai/service.py:118` 写入 `ai_call_records` |

## 3. 建议修复方案（不在本单执行）

**推荐方案**：

1. 新增 `AIErrorCode.QUOTA_EXHAUSTED = "quota_exhausted"`（**不可重试**，语义 = 账户余额/配额不足或额度耗尽）；403 **且** body 命中关键词（`quota` / `insufficient_quota` / `balance` / `余额` / `pre_consume`）→ 映射该码；纯 401、或无配额线索的 403 → 维持 `AUTH_ERROR`。
2. 在 `AIError.message` 中附加**脱敏且截断**（≤200 字符；剔除 `sk-` 等密钥特征串）的三方响应摘要 → DATA-009 可直接读数定位，无需另跑脚本复现。
3. 复核语义边界：429 `RATE_LIMITED`（限流，**可退避重试**）与新增 `QUOTA_EXHAUSTED`（额度，**不可重试**）不得混同。

> 安全约束：`errors.py:52` 已声明「message 面向内部日志/降级信号；禁止携带密钥等敏感内容」→ 摘要写入前**必须**做密钥串剔除与长度截断。

**备选方案**：仅在日志侧补打三方摘要（`logger.warning`），不改 DATA-009 契约 —— 留痕仍不完整，不推荐。
