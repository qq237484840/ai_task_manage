# BUG-003 —— `MockVisionProvider` 挂接建议读取了错误的 context key（Mock AI 链路失效）

- **BUG ID**：BUG-003 ｜ **状态**：**Verified（`Task-013` 修复 + `Task-013-D1` API 面补证 + `Task-014` 去替身复审经 PM 亲手判别力复现通过，2026-09-10）** ｜ **发现日期**：2026-09-10
- **发现者**：`AGENT-M002`（`m002-dev`，执行 `Task-011` ④ 验收时）
- **修复执行**：**`Task-013`（`AGENT-AI` / `ai-dev`）** ｜ **复核**：Project Master（修复后复审 = `Task-014`）
- **影响范围**：`app.core.ai` Mock Provider；M002 `API-M002-007`（挂接建议）；验收剧本 5/6 的 Mock 链路
- **严重级别**：**中**（Mock 降级路径下挂接建议恒为空，但前端「待挂接」+ 手工挂接兜底可用；无数据损坏、无安全影响）

## 1. 现象

在 Mock 配置（ADR-011 默认降级）下上传作业照片后：

- `GET /api/v1/photos/{photo_id}/link-suggestions` 恒返回 `{photo_id, status:"unassigned", suggestions:[]}`；
- 前端 `PhotoListView.vue` 中照片全部落入「待挂接」分区，依赖手工挂接完成后续流程。

## 2. Root Cause

| # | 环节 | 证据 |
| --- | --- | --- |
| 1 | `AIService.suggest_photo_links` 注入 context key 为 `candidates` | `backend/app/core/ai/service.py:197`：`context: dict[str, Any] = {"candidates": candidate_payload}` |
| 2 | prompt 模板变量同样使用 `$candidates` | `backend/app/core/ai/prompts/photo_link_suggest.v1.txt:4`：`$candidates` |
| 3 | `MockVisionProvider._mock_payload` 却读取 `candidate_subjects` | `backend/app/core/ai/providers/mock.py:141`：`return _suggest_links(list(context.get("candidate_subjects", []) or []))` |
| 4 | key 不匹配 → `_suggest_links` 收到空列表 → suggestions 恒空 | Mock 输出 `{links:[], confidence:0.0}` |

**为何未在 Task-006 发现**：Task-006 的横切 AI 测试直接调用 `MockVisionProvider.analyze()` 并显式传入 `context={"candidate_subjects":[...]}`，未走 `AIService.suggest_photo_links` 的真实装配路径，导致 key 约定未对齐。

## 3. Fix（原登记；已由 `Task-013` 执行，见 §7.1）

**推荐方案**：让 Mock Provider 与 `AIService` / prompt 保持一致，将 `mock.py:141` 的 `candidate_subjects` 改为 `candidates`。

```python
# backend/app/core/ai/providers/mock.py:141
return _suggest_links(list(context.get("candidates", []) or []))
```

**备选方案**：`AIService` 同时注入 `candidate_subjects`（冗余字段），但不改变 prompt 与真实 Provider 调用路径，不推荐。

## 4. 真实三方 Provider 覆盖情况

- **真实三方未覆盖（无密钥）**：仅验证 Mock 链路。若真实 Provider 的 prompt 约定也为 `$candidates`，则真实链路无此 key 错误；但需 PM 在修复任务中补充真实 Provider 回归。
