# CR-006：M002 照片域三项增强（窗口归属 / AI 失败可观测 / 重试异步化）

- **提案人**：Project Master ｜ **日期**：2026-09-14 ｜ **状态**：**Proposed（待用户批准）**
- **关联**：`TD-005`（未挂接照片无窗口归属）、`BUG-005`（失败原因留痕，本 CR 为其**下游消费**）、`BUG-007`（重试超时，本 CR 提供**根治**）、`REQ-011`（R4 增强）
- **变更类型**：M002 契约扩展（**非破坏性**，走新增/可选参数与新增端点）+ DATA-003 字段修订 + 迁移
- **三个子项独立可分批批准**（A / B / C）

## 子项 A —— `TD-005`：未挂接照片的窗口归属

**问题**：`photos.task_id`（窗口级）**仅在「首条挂接确认」时写入**（`link_service.py:376-388` + `photo_repository.py:150-155`）→ `unassigned`/`suggested` 照片**无任何窗口归属**（表亦无 `belong_date`）→ 无法按窗口过滤/统计/展示（`REQ-011` 因此只能用「学生级」宽口径）。

**变更**：
1. `photos` 新增冗余列 **`belong_date`**（+ 可选 `group_key`），**上传时**由 M002 解析并落库
   - 解析方式：M002 已有「按 `(student_id, category, belong_date)` 惰性 `ensure_group`」的通路（经 M001 契约内接口 `ensure_group`）→ 复用其返回的窗口上下文；`category` V1 恒 `school`；
   - 写入时机：`PhotoRepository.create`（与 `task_id` 冗余解耦，**不再等挂接确认**）。
2. `GET /photos` 新增可选查询参数 **`belong_date`** / **`group_key`**（缺省不过滤 → **向后兼容**）。
3. DATA-003 字段修订 + 迁移脚本（V1 无历史生产数据 → 允许「重建 + 回填未挂接照片」）。

**影响**：`REQ-011` 卡片可升级为**本任务窗口口径**（替换学生级宽口径）；作业页未挂接照片可归入窗口；后续窗口级统计/清理可用。
**风险**：上传路径多一次窗口解析（M002 → M001 契约内接口，**已有调用**，仅提前到上传时）；迁移期间新旧数据并存（V1 无生产数据，风险低）。

## 子项 B —— AI 失败原因对用户可见（消费 `BUG-005` 修复成果）

**问题**：`API-M002-007` 在 AI 不可用时**静默降级**（契约明文「AI 不可用时静默降级、不报错」），前端只能猜到「可能不可用」，**看不到真实原因**（`quota_exhausted` / `server_error` / 502 …）。

**变更**：`GET /photos/{photo_id}/link-suggestions` 响应**新增可选字段**（非破坏）：
```json
{
  "photo_id": "...", "status": "unassigned", "suggestions": [],
  "last_attempt": {
    "status": "error", "error_code": "quota_exhausted",
    "error_message": "三方账户余额/配额不足… | 三方摘要: …",
    "model": "qwen3.8-flash", "mock": false, "at": "2026-09-14T…"
  }
}
```
- 数据来源：**DATA-009**（`ai_call_records`）按 `photo_id` 取最近一次 `photo_link_suggest` 记录；
- `last_attempt` 为 `null` 表示无记录；**仅返回脱敏后的 message**（继承 `BUG-005` 的脱敏 + 截断约束）；
- 前端据此把「可能暂不可用」升级为**可操作的具体原因**（如「账户余额不足，请联系管理员充值」）。

**影响**：M002 契约 v0.4.2 → v0.4.3（响应体 +1 可选字段）；DATA-009 **无需变更**（已有字段足够：`status`/`error`/`model`/`mock`/`created_at`）。
**风险**：需按 `photo_id` 查 AI 记录 → `ai_call_records` 需有可按 `photo_id` 检索的关联（当前 `input_ref` 承载该语义）→ **实施前须核验 `input_ref` 是否可靠承载 `photo_id`**；若不可靠，本子项需附带「记录补充 `photo_id` 列/索引」的小变更。

## 子项 C —— `API-M002-007` 重试异步化（`BUG-007` 根治）

**问题**：`retry=true` 在请求内**同步**跑 AI（实测 15.6s），与前端超时强耦合（`BUG-007` 已止损未根治）。

**变更（非破坏，保留同步路径）**：新增端点
```
POST /api/v1/photos/{photo_id}/link-suggestions/retry
→ 202 { "photo_id": "...", "status": "accepted", "attempted_at": "..." }
```
- 触发即返回（后台执行，沿用既有建议调度器；失败由 DATA-009 留痕 + 子项 B 暴露）；
- 前端：触发后**轮询** `GET /photos/{id}/link-suggestions`（既有接口）直至有建议或超时；
- **保留** `GET ...?retry=true` 的同步语义（向后兼容；`REQ-011` 卡片与作业页可择机迁移到异步路径）。

**影响**：M002 契约 v0.4.3 → v0.4.4（+1 端点）；浏览器级可长时间离开页面（不占请求）。
**风险**：异步执行需保证**幂等**（同一照片并发触发 → 只跑一次，沿用 `has_active_link` 前置）；后台任务异常需可观测（DATA-009 + 日志）。
