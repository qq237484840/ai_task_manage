## 项目是什么

- **项目名称**：中小学生 AI 作业与学习成长综合评定系统
- **当前版本（V1 MVP）**：AI 每日作业智能评定系统 —— 一个可以真实运行的作业评定闭环
- **仓库名**：`AI.TaskManage`（git 仓库名，与产品名无绑定关系）

## V1 核心闭环

```text
创建作业任务 → 学生上传作业照片 → AI 识别 → 任务匹配
→ 作业分析 → 作业质量评价 → AI 教师评价 → 今日作业综合报告
```

## 为什么开发

- 让"作业评定"可规模化、可解释、可追溯，而不是依赖教师逐一主观判断
- AI 评价必须**基于可观察行为**，不武断给学生贴"态度/能力"标签（PD 见 `docs/adr/ADR-003.md`）

## 解决什么问题

- 每日作业的采集、识别、评定、反馈链路冗长且难以持续
- 传统 AI 评价常输出主观结论、无法追溯、评分规则不可配置、被单一模型绑定
- 学生成长数据（V2+）需要以 V1 的可追溯评定数据为基础，V1 只留扩展边界，不提前实现

## 项目目标

- **V1 唯一目标**：打通"创建作业 → 上传 → 识别 → 匹配 → 质量评价 → 教师评价 → 今日报告"完整闭环，让真实用户能完成一次完整作业评价
- 模块化、可测试、可扩展、配置化；AI Provider 抽象化；评价全链路可追溯
- 每个版本独立可运行、可验证

## 用户是谁

- **V1 身份模型（已确认，ADR-005）**：纯家庭模式 —— 家庭账号（家长/监护人）为使用者主体，一个家庭可维护多名学生档案
- 语义映射（对应需求原文的"教师/学生/家长"）：家长 = 布置作业任务与查看报告者；学生档案 = 作业评定对象（上传照片时选择对应档案）
- 真实教师/班级/学校体系明确不在 V1 内：禁止学校管理/班级管理/复杂教师平台/多租户（注：学生档案关联的"学校基础字典"为全局共享只读公共资料（seed 预置），系限定例外、非学校管理域，见 `docs/adr/ADR-008.md` / `docs/requirements/REQ-009.md`）

## 核心业务是什么

- 作业任务管理 → 作业图片采集 → AI 作业识别 → 作业任务匹配 → AI 作业质量评价 → AI 教师评价与改进建议 → 今日作业综合报告
- V1 评分仅代表「今日作业完成质量」，不解释为「学习能力评分」

## V1 范围控制（禁止提前开发）

禁止：知识图谱、长期学习画像、自动组卷、个性化训练、阶段测评、学校管理、班级管理、复杂教师平台、多租户等。
未来所需支持只允许**预留扩展字段/接口/模块边界**，不允许提前实现（见 `docs/adr/ADR-002.md`）。

## 核心约束

- 模块 ID 需求命名 `M01~M07` 映射为本项目正式 `M001~M007`（别名对照，见 `MODULE_REGISTRY.md`）
- 开发顺序强制：M001→M002→…→M007→全系统回归，前序未验收不得进入下一核心模块
- 每个模块完成后交付 12 项文档产物（模块说明/功能/文件清单/API/数据结构/AI Prompt/配置/测试/已知问题/对外依赖/对模块接口/扩展点）

## 非功能要求

- AI 抽象：至少抽象 Vision / OCR / LLM Provider，业务不绑定单一模型
- AI 调用记录：model、prompt_version、request_id、latency、token_usage、result、confidence、error
- 全链路可追溯：原始图片→预处理→OCR→AI 输入→Prompt 版本→AI 输出→规则处理→最终评价
- AI 评价原则：不武断、可观察行为表述、判断结果+依据+置信度、允许"无法判断"进入人工/重拍
- 评分权重配置化不硬编码；Prompt 不散落代码；无巨型 Service/Controller；日志完整、异常可追踪
