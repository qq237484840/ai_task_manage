## 1. 原始偏差（用户提出的 3 条修正）

1. **任务模块理解错误**：任务是上传一张照片，通过大模型分析"今日任务是什么"，整理成子任务；任务上传**无需填写内容**，直接上传照片；命名与归类逻辑与作业一致。
2. **「照片」菜单应改名「作业」**：每天的作业有一个主表，显示完成作业是星期几（周几）、具体日期等；每周作业分组、按周次命名；周一到周四如实显示，周五到周日上传的取名为"**周末作业**"；**每天凌晨 4 点到第二天凌晨 4 点归为当天**（如 9/9 20:00 至 9/10 03:00 上传，都归 9/9 周三）。
3. **家长维护 + AI 挂接 + 复核后分析**：作业上传后家长可维护；大模型先按作业内容自动挂接到当天任务的**子任务**；家长复核后，大模型才开始分析完成情况。

## 2. 决策清单（A~F）

### A. 任务输入源

- **A1** 任务输入源 = 图片 **/** 文本 **/** 聊天记录（多段混合）。上传**接口与数据表公用**，`kind` 由**入口（菜单）决定**，不由家长选择：菜单「任务」内上传 → `task_spec`；菜单「作业」内上传 → `homework`。
- **A2** 微信小程序**无"接收聊天记录"开放接口**（仅有 `onShareAppMessage` 转发小程序卡片）→ 降级路径 = **复制文本 → 粘贴到输入框**；数据模型按「文本块 + 图片块」**多段**设计，兼容截图/粘贴/手打三种来源。
- **A3** 同一天允许多次上传任务照片，AI 自动分析并归集：**同学科 → 追加内容项**（不去重，家长可删）；**新学科 → 新建子任务**。
- **A4** 内容项（`task_contents`）V1 **只建表、只读展示、不参与挂接与判定**。

### B. 归属与聚合（双层模型）

- **B1 事实层按天**建主任务，唯一键 = **`(student_id, category, belong_date)`**（天粒度）。
- **B2 归属边界**：`AT_DAY_CUTOFF`（默认 `04:00`，**可配置**），`belong_date = (ts − cutoff).date()`；时区固定 **`Asia/Shanghai`**（`AT_TIMEZONE`）。时间戳仍按 UTC 存储，仅在归属计算处转换。
- **B3 周次**：`week_index` = 学期开始日**所在周的周一**起算第 N 周；新增 `AT_TERM_START`（学期开始日）与 `AT_TERM_END`（学期结束日，学期外=假期）。
- **B4 周末 / 周次 / 假期 = 聚合层概念**，**不再是唯一键的组成部分**；**每个 `belong_date` 都有一个聚合**（最小聚合 = 1 天），周一到周四各自一个聚合，周五~周日合并为一个"周末作业"聚合（覆盖 周五 04:00 ~ 周一 04:00）。
- **B5 配置锁定语义（关键）**：
  - 配置变更**只影响未聚合的对象**；**已聚合的按老配置**执行（示例：小明周五已上传任务或作业 → 周六修改 `AT_DAY_CUTOFF` 对其**不生效**；小红周五、周六均未上传 → 按新配置）。
  - **锁定粒度 = 每个 `(学生, 聚合对象)` 独立锁**（同一日期，不同学生可用不同配置版本）。
  - **锁定触发条件 = 数据写入**（任务解析完成 / 作业照片上传）；**纯浏览不锁配置**。
  - 实现：`task_groups.policy_version` 于聚合生成时写入当时生效配置版本，后续**追加数据不改**该字段；未生成的聚合按**当前生效**配置生成。
- **B6 假期**：解析器策略化（`WindowResolver`），V1 按**自然周**分段聚合（如 `H:2026-07-01.W1`）。**假期"完成计划"与评估报告/汇总简报 → 后置 V2**。
- **B7** 占位主任务（作业先到、任务照片未到）：`tasks.title` 由窗口解析器**自动生成**（如"09-09 周三"），家长可改；以 `spec_status = placeholder | parsed | confirmed` 区分。
- **B8 手工改归属日的连锁规则**：① 重算快照（`belong_date`/`week_index`/聚合成员）；② 迁移主表 FK（目标聚合无则建）；③ 源聚合变空则删；④ **已被完成分析消费的作业禁改**（V1 直接拒绝）；⑤ 记审计（操作人/原值→新值/时间）。**新增**：跨聚合迁移须同步更新 `photo_subject_links` 的挂接目标。

### C. 挂接 / 复核 / 分析

- **C1 挂接粒度 = 子任务(学科)**，且允许 **N:N**（1 照片 → 多学科；1 学科 → 多照片）。**必须放开 M002 现有「1 照片 → 1 个 `(task_id, subject, group_no)` 段」的强约束**。
- **C2 挂接与判定都落聚合层**（判定单元 = `task_group_subjects`），**不落事实层**。理由：周末按 3 天计，实际完成可能是"周五一部分 / 周六无 / 周日一部分"等组合，而任务（布置）可能是这三天中某一天上传 → **天级判定逻辑矛盾**。故子任务(学科)从事实层**上移到聚合层**。
- **C3 复核单元 = 逐张照片**（复用 M002 建议流程：accept / reject / 改挂）+ 子任务汇总视图；**完成分析为窗口级门控**：该聚合下全部照片挂接确认后才自动触发分析，未确认完则提示"待复核 N 张"。
- **C4 触发时机 = 上传成功即异步触发挂接**（幂等，只处理未挂接照片）。
- **C5 分析结论 = 草稿**，家长确认后成为正式结论。产物 = 聚合子任务级：`完成 / 部分完成 / 未完成 / 无法判断` + 依据照片 + 置信度。
- **C6 失败降级**：LLM 超时 / 返回不合规 → 照片保持 `unassigned` 并提示家长**手工挂接**（现有手工路径必须保留）。
- **C7 隐式确认链**：链路 T 的解析结果（子任务/内容项草稿）由家长在任务页确认；**也支持在"确认作业完成情况"时一并自动落库**（免返回任务页）。**前提：确认页必须展示"本次将一并落库的任务解析摘要"**（学科 + 内容项列表），避免家长盲确认。
- **C8 链路 T 与链路 H 不分先后**（并行）。仅 `school` 一种任务类型时，**主任务级**按归属窗口**确定性匹配**；**子任务(学科)级仍需 AI 判定**（照片内容 → 学科）。后续开放多任务类型时，改由家长手工匹配「任务(布置) ↔ 作业(结果)」。

## 4. V1 必做 / 不做

### 4.1 必做（10 项）

1. **归属引擎**：`belong_date`（4 点边界 / Asia/Shanghai / 可配）+ `week_index` + 周末聚合 + 假期自然周聚合。
2. **事实层改造**：`tasks` 字段与唯一键；`task_contents`、`task_spec_sources`；**`task_items` 废弃**。
3. **聚合层新建**：`task_groups`（含 `policy_version`）+ `task_group_subjects`。
4. **链路 T**：菜单「任务」上传（图片 **或** 粘贴文本）→ AI 解析 → 草稿 → 家长确认 / 隐式确认。
5. **链路 H**：菜单「作业」上传（**不填任何内容**）→ AI 挂接建议 → 家长逐张复核 → 窗口级门控 → 家长确认 → 触发完成分析。
6. **完成情况分析**：聚合子任务级结论（完成/部分完成/未完成/无法判断 + 依据 + 置信度），草稿 → 确认。
7. **兜底**：AI 失败 → 照片 `unassigned` + 手工挂接；手工改归属日（B8 连锁）。
8. **前端**：菜单「照片」→「**作业**」；列表按周次分组 + 周末聚合展示；任务列表页 **422 修复**。
9. **配置**：`AT_TIMEZONE` / `AT_TERM_START` / `AT_TERM_END` / `AT_DAY_CUTOFF`。
10. **LLM 接入层** `app/core/ai/`。

### 4.2 明确不做（后置 V2）

假期完成计划 · 评估报告 / 汇总简报 · 多任务类型（`category` 仅 `school`，字段预留）· 内容项级判定 · 聊天记录转发（改粘贴文本）· 微信小程序（V1 仅 web）。
