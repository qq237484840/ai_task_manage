## Requirement

### R1 —— 任务 = 按天、由输入源解析出的布置记录

- 任务**不再由家长手工录入标题与题目**：家长在「任务」入口上传**图片**或**粘贴文本**（多段可混排，`task_spec_sources`），上传时**无需填写任何内容**。
- AI 解析出「今日任务」→ **子任务（学科）+ 内容项**草稿；家长确认后生效（`spec_status = placeholder | parsed | confirmed`）。解析结果的**隐式确认**（在确认作业完成情况时一并落库）见 R4。
- 事实层按天唯一：`tasks` 唯一键 = **`(student_id, category, belong_date)`**；`category` V1 仅 `school`（字段预留多任务类型）。
- 命名与归类逻辑与作业一致：`title` 由窗口解析器**自动生成**（如「09-09 周三」），家长可改。
- **`task_items`（逐题建模）废弃**，V1 不再写入（表保留以兼容旧数据）。原定天级 `task_subjects` **取消**。

### R2 —— 作业按天归属 + 周次分组 + 周末合并

- 菜单「照片」更名「**作业**」；每天作业有主表，展示**周几 + 具体日期**。
- 归属日边界 = 凌晨 **4 点**（`AT_DAY_CUTOFF`，可配）：`belong_date = (ts − cutoff).date()`；时区固定 `Asia/Shanghai`（`AT_TIMEZONE`）；时间戳仍按 UTC 存储，仅在归属计算处转换。例：9/9 20:00 与 9/10 03:00 上传 → 同归 **9/9 周三**。
- 每周按 `week_index` 分组（起算 = `AT_TERM_START` 所在周的**周一**）；周一到周四如实显示；**周五 04:00 ~ 周一 04:00 合并为「周末作业」**；学期外（`AT_TERM_END` 之后）按**自然周**分段。
- **每个 `belong_date` 都有一个聚合**（最小聚合 = 1 天）。

### R3 —— 挂接与判定落聚合层（不落事实层）

- 聚合层结构：`task_groups`（含 `policy_version`）→ `task_group_subjects`（**★判定单元**，按 subject 合并）→ `photo_subject_links`（**N:N**）→ `completion_analyses`。
- 挂接粒度 = 聚合子任务（学科），**允许 N:N**（1 照片 → 多学科；1 学科 → 多照片）。
- 判定粒度 = **聚合子任务级**，结论 = `完成 / 部分完成 / 未完成 / 无法判断` + 依据照片 + 置信度。**ADR-010 的逐题判定作废**；端到端直判、可观察依据、置信度、`无法判断` 出口、家长复核、不武断底线（ADR-003）**由 ADR-013 继承**。
- 判定落聚合层的理由：周末跨 3 天，实际完成可能是「周五一部分 / 周六无 / 周日一部分」等组合，而**布置可能仅其中一天上传** → 天级判定逻辑矛盾。

### R4 —— 挂接 → 复核 → 分析（窗口级门控）

- 上传成功后**异步触发挂接**（幂等，只处理未挂接照片）；LLM 超时 / 返回不合规 → 照片保持 `unassigned` 并提示**手工挂接**（现有手工路径必须保留）。
- 复核单元 = **逐张照片**（复用 M002 建议流程：accept / reject / 改挂）+ 子任务汇总视图；**完成分析为窗口级门控**——该聚合下全部照片挂接确认后才自动触发分析，未确认完则提示「待复核 N 张」。
- 分析结论为**草稿**，家长确认后成为正式结论。
- 链路 T 解析结果由家长在任务页确认；**也支持在「确认作业完成情况」时一并自动落库**。前提：确认页**必须展示本次将一并落库的任务解析摘要**（学科 + 内容项列表），避免盲确认。
- 链路 T 与链路 H **不分先后**（并行）。仅 `school` 一种任务类型时，主任务级按归属窗口**确定性匹配**；**子任务（学科）级仍需 AI 判定**（照片内容 → 学科）。

### R5 —— 配置锁定语义

- 配置变更**只影响未聚合对象**；**已聚合按生成时配置**执行（`task_groups.policy_version` 于聚合生成时写入，后续**追加数据不改**该字段）。
- 锁定**粒度** = 每个 `(学生, 聚合对象)` **独立锁**（同一日期，不同学生可用不同配置版本）。
- 锁定**触发条件** = **数据写入**（任务解析完成 / 作业照片上传）；**纯浏览不锁配置**。
- `belong_date` / `week_index` 上传时**固化**，配置变更**不回算历史**。配置项登记见 `docs/CONFIGURATION.md`。

### R6 —— 手工改归属日的连锁规则

① 重算快照（`belong_date` / `week_index` / 聚合成员）；② 迁移主表 FK（目标聚合无则建）；③ 源聚合变空则删；④ **已被完成分析消费的作业禁改**（V1 直接拒绝）；⑤ 记审计（操作人 / 原值→新值 / 时间）；⑥ **跨聚合迁移须同步更新 `photo_subject_links` 的挂接目标**。

### R7 —— 横切：LLM 接入层

- 新增 `app/core/ai/`（provider 抽象 + prompt 管理 + 结果 schema 校验 + 降级），**不塞进业务模块**；承接 `ADR-011`（真实三方默认、Mock 降级为测试桩 / 离线降级）。**执行方 = `AGENT-AI`**（`ADR-014` 决议 3，任务书 `docs/agents/Task-006.md`；启动前置 = `CHANGE-003` ② 评审 APPROVED）。

## V1 范围

- **必做 10 项**：归属引擎（`WindowResolver`）/ 事实层改造 / 聚合层新建 / 链路 T / 链路 H / 完成情况分析 / 兜底与手工路径 / 前端（「作业」菜单 + 周次分组 + 422 修复）/ 配置 4 项 / LLM 接入层。逐项见 `CLARIFICATION-2026-09-10.md` §4.1。
- **明确不做（后置 V2）**：假期完成计划 · 评估报告 / 汇总简报 · 多任务类型（`category` 仅 `school`）· 内容项级判定 · 聊天记录转发（改粘贴文本）· 微信小程序（V1 仅 web）。见 §4.2。
- **边界决议（2026-09-10，`ADR-014`，原待确认项 Q1/Q2 已关闭）**：上表 **必做 10 项即 V1 全量范围**（唯一清单）；**M003/M004 职责并入 M001（链路 T）/ M002（链路 H）**（Module ID 保留，状态 Deferred）；**`REQ-005`~`REQ-007` → Deferred（后置 V2）**；横切 `app/core/ai/` 执行方 = **`AGENT-AI`**（Task-006）。

## 验收标准

- 通过 `CLARIFICATION-2026-09-10.md` §5 **验收剧本 7 条**：4 点边界归属 / 周末 3 天聚合 / 配置锁定按学生隔离 / 链路 T 解析确认 / 链路 H 挂接复核分析 / LLM 降级手工兜底 / 任务列表页无 422。
- 双层模型落地：事实层按天唯一、聚合层落库且 `policy_version` 正确锁定；跨聚合迁移同步挂接目标。
- 配置变更不回算历史（已聚合对象不受影响）。
