## Requirement

V1 闭环第二环节：上传作业照片（先采后认）。

> **修正后口径（随 `CR-003`，2026-09-10）** —— 上传入口分「任务」/「作业」；**「作业」上传不填任何内容**；归属由「登记单内学科作业段（1:N）」放开为「**聚合子任务 N:N**」。权威源 `CLARIFICATION-2026-09-10.md`，完整语义见 `REQ-010`。

- 学生/家长上传作业照片（拍摄或相册选择）；**「作业」入口上传时无需预选任务/学科、无需填写任何内容**，由 AI 挂接建议 + 家长逐张复核兜底
- **归属 = 照片 ↔ 聚合子任务（学科）的 N:N 挂接**（`photo_subject_links`，DATA-016）：1 张照片可挂多个学科，1 个学科可挂多张照片
- **归属日按天固化**：`belong_date` = `(ts − AT_DAY_CUTOFF).date()`（默认凌晨 4 点为界，时区 `Asia/Shanghai`）；`photos.task_id` 降级为**窗口级归属**；`photos.subject` / `photos.group_no` **废弃**
- 图片质量检测：对模糊、过暗/过亮、倾斜、遮挡、缺页等情况检出，不合格提示重新拍摄（与"AI 无法可靠判断 → 不猜"原则衔接，见 REQ-008）
- 必要的图片预处理（如矫正、增强）由 M002 或识别前链路完成（边界待模块契约确认）
- 原始图片与预处理图片需被记录（可追溯链起点）
- **触发**：上传成功后**异步触发挂接**（幂等，只处理未挂接照片）；LLM 超时/返回不合规 → 照片保持 `unassigned` 并提示**手工挂接**（手工路径必须保留）

## 验收标准

- 未经预选任务/学科即可上传入库，照片初始状态 `unassigned`
- 明显不合格图片能被检出并引导重拍
- AI 挂接建议可被逐张 accept / reject / 改挂；**全部确认后**才触发窗口级完成分析（未确认完提示「待复核 N 张」）
- LLM 不可用时手工挂接路径可用
