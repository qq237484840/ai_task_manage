- **来源**：用户「V1 MVP 总控 Agent 指令」§二（M02 作业图片采集）/ §五 / §十一（重新拍摄）/ §十五
- **优先级**：P0（V1 范围强制）
- **状态**：Approved（2026-09-08，V1 需求基线冻结；PD-001~008 全部确认，见 ADR-002~007/ASM-001~011）

- **关联数据**：DATA-003（作业提交与图片）等
- **实现/测试**：待需求确认后设计

## Requirement

V1 闭环第二环节：学生上传作业照片。

- 学生/家长上传作业照片（拍摄或相册选择），图片与某条作业任务关联
- 图片质量检测：对模糊、过暗/过亮、倾斜、遮挡、缺页等情况检出，不合格提示重新拍摄（与"AI 无法可靠判断 → 不猜"原则衔接，见 REQ-008）
- 必要的图片预处理（如矫正、增强）由 M002 或识别前链路完成（边界待模块契约确认）
- 原始图片与预处理图片需被记录（可追溯链起点）

## 影响分析摘要

- 影响模块：M002（本模块）
- 依赖：M001（读取任务）
- 消费者：M003（取图识别）、M007（报告引用提交信息）
- 影响数据：作业提交/图片实体（新建）
- 风险：上传形态依赖平台形态（PD-003）；图片大小/存储方案待确认

## 验收标准（草案，待确认）

- 能针对已发布任务上传图片并成功入库
- 明显不合格图片能被检出并引导重拍
- 图片可被 M003 读取进入识别

## 待确认点（历史，已确认）

- PD-003 平台形态 → 移动优先 H5（ADR-004）
- 图片质量检测的判定策略 → **本地规则先行**（D1 / PD-010）

> 变更提示（2026-09-08，CR-001/CR-002 相关，PD-014/015/017~024）：采集模式重构为**先采后认** —— 学生按"上传批次"批量上传照片（不要求预选任务/学科），照片先质检入库为 `unassigned`，由 AI（M003）建议归属到登记单内学科作业段（`suggested`），低置信/失败由家长（或学生本人）手动关联/驳回兜底（`assigned`/`rejected`）；**完成程度由内容级判定链（M003 识别 + M004 逐题对齐判定，ADR-010）回写，M002 不再输出覆盖二值化完成度（v0.3.0）**。身份为两级主体（学生自主上传、家长兜底，ADR-009/ACR-001）。详细语义精校已随批准包（CR-001/ACR-001/CR-002/ACR-002 Approved）纳入 M001 变更执行与 M002 v0.3.0。
