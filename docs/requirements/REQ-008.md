## Requirement

以下治理约束作为 V1 全部模块的强制要求落实（写入各模块 DoD）：

### AI 抽象与调用记录
- AI 能力抽象为 Provider，不绑定单一模型；至少抽象 Vision / OCR / LLM
- 每次 AI 调用记录：model、prompt_version、request_id、latency、token_usage（可用时）、result、confidence、error
- 未来可替换模型（架构上可换，V1 不实现切换 UI）

### 全链路可追溯
- 任意 AI 评价可回溯：原始图片 → 预处理图片 → OCR 结果 → AI 输入 → Prompt 版本 → AI 输出 → 规则处理 → 最终评价

### 异常原则（AI 不猜）
- AI 无法可靠判断的内容不得猜测，允许"无法判断"
- "无法判断"进入人工确认流程或提示重新拍摄

### 代码质量与配置化
- 模块化 / 可测试 / 可扩展 / 配置化 / 日志完整 / 异常可追踪 / API 边界清晰
- 禁止：巨型 Service/Controller、AI Prompt 散落代码、评分规则散落代码、硬编码模型名称、硬编码评分权重
- 每次执行流程：分析 → 计划 → 修改 → 测试 → 检查 → 文档 → 汇报；发现歧义采用最小可行实现，不扩大需求

## 影响分析摘要

- 影响：所有模块的架构、设计、编码规范、测试与文档
- 共享代码：AI Provider 抽象、统一调用记录、日志、异常处理（进入 shared/infrastructure，禁止业务逻辑混入）
- 风险：约束执行靠 DoD 审查保障（RISK 相关项见 RISK_REGISTER.md）

## 验收标准（草案，待确认）

- V1 全链路完成一次作业评价后，可完整输出其追溯链
- 存在至少一个"无法判断→重拍/人工"的可运行路径
- 评分权重与 AI 模型名均为配置项（非硬编码）
- 满足 §十五 全部完成标准链路
