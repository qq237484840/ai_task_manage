## 1. 主线原则（用户定稿）

1. **功能主线驱动**：开发顺序与验收里程碑按功能域（A/B/C/D）组织，逐条对应用户核心需求，域内可端到端演示。
2. **保留模块组织**：代码/文档仍按 M001~M007 模块与契约治理（模块开发顺序 M001→…→M007 保留），功能域跨模块串联。
3. **一期全做（MVP 全部核心功能）**：6 项核心需求全部进入 V1，按 MVC（Model-View-Controller）三层落地，不做分期裁剪。
4. **真实三方 AI 为默认运行路径**（修订 ADR-007/ASM-010）：OCR/Vision/LLM 对接真实第三方 Provider；Mock 仅作测试桩与离线降级。
5. **内容级判定**（重开 ADR-003/006）：布置登记精确到题，匹配=照片内容↔布置题目逐题对齐并判完成/对错，大模型综合评分；识别/判定不可靠时保留"无法判断"→ 家长复核兜底。

## 4. 主线阶段与里程碑（验收以功能域为单位）

> 开发仍按模块顺序执行；以下里程碑为**域级验收点**，可按顺序推进，域间存在数据流依赖（A→B→C→D）。

### 里程碑 M-A：学生自主采集闭环可用（域 A）
- **用户价值**：学生/家长把"今日作业布置/登记单"和"今日完成的作业"都能拍照录入系统
- **验收场景（E2E）**：
  1. 学生用手机拍摄布置页/登记单 → 上传 → 大模型结构化出"今日作业清单（学科 + 条目）"草稿
  2. 学生/家长对识别草稿确认补正 → 生效为登记单（含学科作业段/题目条目，M001 数据面经 CR-002）
  3. 学生自主拍摄完成作业（多图/分科/分页）→ 质量检测 → 预处理 → 入库
- **DoD 通过条件**：域 A 场景在**真实三方 AI** 与 **Mock 离线**两种模式均可跑通；照片质量不合格可重拍引导

### 里程碑 M-B：家长复核确认闭环可用（域 B）
- **用户价值**：家长能复核"哪张照片对应哪份登记单/哪科作业"，纠正 AI 归属建议，人工兜底
- **验收场景（E2E）**：
  1. 采集照片自动（或半自动）归属建议到登记单/学科作业段
  2. 家长复核清单 → 一键确认 / 拖动改派 / 标记无关 → 归属生效（assigned/rejected 状态机，含并发冲突处理）
  3. 学生子账号自主操作本人照片归属，家长可见全部并可兜底
- **DoD 通过条件**：归属状态机全部路径可用；误归属可纠正且审计留痕；越权（学生访问他人）被拒

### 里程碑 M-C：内容级匹配 + 家长兜底可用（域 C）
- **用户价值**：大模型把"布置的题目"和"照片里的完成作答"逐题对上，判完成/对错；拿不准的交家长拍板
- **验收场景（E2E）**：
  1. 布置登记单已精确到题（登记单题目条目）
  2. 完成作业照片 → 识别结构化作答 → 与登记单题目**逐题对齐**（可含题型/作答位置）
  3. 输出每题判定：完成 / 未完成 / 无法判断（含依据与置信度）；客观与主观题按 ADR-010（内容级全判，主客观全判）给出
  4. 低置信/无法判断/家长异议 → 家长兜底界面复核 → 复核结果回写
- **DoD 通过条件**：内容级判定结果可逐题解释、可追溯；家长复核路径完整；"不猜"仍有效（无法判断不硬猜，只标记）

### 里程碑 M-D：AI 综合评判 + 每日报告定稿可用（域 D）
- **用户价值**：大模型分析完成情况 → 综合评判 → 生成每日报告，家长确认后定稿存档
- **验收场景（E2E）**：
  1. 域 C 判定结果聚合 → M005 六维+综合（含正确度，主客观全判口径）+ M006 AI 教师评语 → 今日报告草稿
  2. 家长复核草稿（低置信/异议/无法判断逐项过）→ 确认定稿归档（草稿与复核记录保留）
  3. 报告/评语可追溯到照片、识别、判定、评分各环节
- **DoD 通过条件**：报告草稿→复核→定稿全链路可跑；评分与评语基于证据链、配置化权重；全链路 AI 调用记录完整

### 里程碑 M-END：V1 全量回归与发布
- 四域 E2E 全链路回归（真实三方 + Mock 双跑）；API/数据/权限矩阵回归；文档回填一致
- 满足 REQ-001~009 与治理基线（ADR-002~004 范围边界不破坏）
