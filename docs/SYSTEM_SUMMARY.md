## 系统目标

V1 = **AI 每日作业智能评定系统**：让真实用户完成一次完整作业评价。
评分只代表「今日作业完成质量」，不是「学习能力评分」。详细见 `PROJECT.md`。

## 核心领域（Domain）

V1 规模较小，暂不建 Domain 层（按 `INDEX.md`，规模扩大时再引入）。业务域即"作业评定"，由 7 个模块覆盖。

## 模块（Module）概览

| Module ID | 名称 | 一句话职责 |
| --- | --- | --- |
| M001 | 作业任务管理 | 创建/维护作业任务（题目、状态），后续正确度评价的对照基准来源之一 |
| M002 | 作业图片采集 | 拍摄/上传作业照片、图片质量检测、预处理与存储引用 |
| M003 | AI 作业识别 | 经 OCR/Vision Provider 把图片识别为结构化内容，带置信度 |
| M004 | 作业任务匹配 | 把识别结果与 M001 任务/题目对齐，给出可观察的匹配依据 |
| M005 | AI 作业质量评价 | 六维度评分（完成度/正确度/完整度/规范度/书写质量/完成质量），权重配置化 |
| M006 | AI 教师评价与改进建议 | 生成"可观察行为"式教师评价 + 分级重写建议 |
| M007 | 今日作业综合报告 | 聚合当日 M005/M006 结果输出综合报告 |

（需求命名 M01~M07 = 正式 M001~M007。Registry：`MODULE_REGISTRY.md`）

## 模块关系

依赖方向（禁止环）：

```text
M002 → M001         （采集时读取任务）
M003 → M002(数据)   （读取图片做识别）
M004 → M001, M003   （任务 × 识别 → 匹配）
M005 → M001, M003, M004（评分需题目基准/识别/匹配）
M006 → M005         （教师评价基于质量评价）
M007 → M001, M002, M005, M006（报告聚合）
```

无环。每个模块只经 API/DTO/Event/Contract 协作，不依赖内部实现。

## 主要数据流

```text
创建任务(M001) ──► 上传图片(M002) ──► 识别(M003) ──► 匹配(M004)
    ──► 六维评分(M005) ──► 教师评价(M006) ──► 今日报告(M007)
              ▲             ▲                ▲
              └── 全链路可追溯记录（图片→OCR→AI输入→输出→规则→评价）
```

实体级数据见 `DATA_MODEL.md`。

## 主要业务流

- **家庭账号（家长）**布置作业任务（ADR-005 纯家庭模式，对应需求语境"教师"）→ 为家庭内**学生档案**上传作业照片 → 系统依次执行 识别→匹配→评分→教师评价→报告
- AI 无法可靠判断时：不猜，允许"无法判断"，进入人工确认或提示重新拍摄
- 重写判断分级：无需重写 / 建议订正 / 建议重写部分题目 / 建议重新完成本项作业

## 关键技术决策

- ADR-001：采用文档驱动 + 总控 Agent 多 Agent 协作治理体系
- ADR-002：V1 范围控制（仅 7 模块闭环，禁止提前开发未来功能）
- ADR-003：AI 评价边界与原则（可观察行为 / 不武断 / 配置化权重 / 分级重写 / 允许"无法判断"）
- ADR-004：技术栈 = 移动优先 H5 + Python FastAPI + SQLite 单体（PD-003 已确认）
- ADR-005：身份模型 = 纯家庭模式（家庭账号 + 学生档案，PD-004 已确认）
- ADR-006：正确度判定 = 分科混合策略（客观题对照参考答案 / 主观题不判对错并注明，PD-005 已确认）【**v0.9.0：已 Superseded → ADR-010**（内容级主客观全判 + 端到端直判），待 ACR-002 批准生效】
- ADR-007：AI Provider = 抽象 + Mock 先行（本地无 key 跑通全链路，PD-006 已确认）【**v0.9.0：已 Superseded → ADR-011**（真实三方默认、Mock 降级测试桩/离线），ACR-002 已批准（2026-09-08），正式生效】
- PD-007/008：默认假设见 ASM-010/011，待用户复核
