## 验收缺陷记录：任务列表页空筛选 → 422（待修）

- **现象**（预览 WebView 实报）：`http://localhost:5174/#/tasks` 首屏抛 `Uncaught (in promise) Error: 请求参数校验失败: Input should be 'draft', 'published', 'in_progress' or 'closed'`
- **触发条件**：进入任务列表页即触发（默认筛选 = 全部状态 / 全部学生）
- **根因链**：
  1. `frontend/src/views/TaskListView.vue:80-85` 直接把 `filters.value.status`（空串）与 `filters.value.student_id`（空串）放进 query；
  2. `frontend/src/api/http.ts` 请求拦截器只注入 Bearer，无 query 空值清洗 → axios 序列化成 `?status=&student_id=`；
  3. 后端 `backend/app/api/v1/tasks.py:48` `status: _TASK_STATUS | None`（严格枚举，单值）→ 空串 422。
- **影响**：任务列表首屏请求失败；`loadTasks` 只有 `try/finally` 无 `catch` → 未捕获的 promise rejection（即 WebView 报错），列表恒空且无 toast 提示，筛选/列表功能实际不可用。
- **同类隐患扫描（已排除）**：`PhotoListView.vue:223-228` 用 `student_id: ... || undefined` 且 `listPhotos` 内部 `...(status ? {status} : {})` 条件展开，无此问题；`student_id` 后端为 `str | None`（仅 `max_length=36`），空串不会 422。
- **建议修复（前端，改动小）**：
  1. `TaskListView.vue` 构造 params 时剔除空值：`...(filters.value.status ? { status: filters.value.status } : {})`，`student_id` 同理；
  2. 更通用方案：在 `http.ts` 请求拦截器统一清理空串/undefined query 参数（一次覆盖所有列表页）；
  3. 给 `loadTasks` 补 `catch` + `toastError`，避免未捕获 rejection。
- **状态**：待修（验收阻塞项，UI 首屏不可用）；修复后需重跑验收：任务列表 / 状态与学生筛选 / 任务详情 / 任务新建。

## 缺陷修复：任务列表页 422（2026-09-10，已完成并实证）

**修复（前端 2 处，均为讨论中记录的方案）**：

**环境提示**：`node`/`npm` 不在 PATH，需前置 `$env:Path = 'C:\Users\Administrator\.workbuddy\binaries\node\versions\22.22.2-2;' + $env:Path`。
